# Спецификация: Living Issue

## Задача

Сравнить существующую редакционную главную с тем же сайтом, начинающимся с открытия собственного travel-выпуска. Контрольная версия и существующие маршруты сохраняются полностью.

## Изоляция и копия

До реализации проверить каталог доступных skills, структуру frontend, локальные components/styles/assets/data и глобальные точки влияния. Применять только полезные проверенные design/frontend skills. Проверить dependencies: подходящего motion stack сейчас нет, поэтому выбран CSS/rAF без установки новой библиотеки.

Перед анимацией создать экспериментальную страницу, показывающую точную копию исходной. Проверить обе версии в браузере. Не изменять исходные компоненты, CSS, данные, фотографии, шрифты, глобальные стили, layout, зависимости или инфраструктуру. Создать отдельные компоненты-копии редакционного дерева и формы; их CSS, неизменяемые data и валидацию заявки импортировать без редактирования. После добавления intro #start находится на исходной шапке/hero с поддержкой клавиатурного фокуса, прежняя форма становится #story и ссылки на форму направляются туда. Все остальные тексты, разделы и поведение совпадают. Не допускаются повторяющиеся ID.

## Арт-дирекшн

Физический образ: тонкий независимый city/travel-выпуск на спокойном редакционном столе. Голос: живой, наблюдательный, собранный. Палитра непосредственно из контрольной: paper #f3f2ee, ink #20211f, blue #172f50, muted #595b57, line #c2c4bd. Шрифты: существующие локальные TC Golos и TC Lora. Не менять идентичность.

Обложка — заметный компактный вертикальный выпуск с крупным мастхедом TRAVEL CLUB, сильным кадром пассажиров/города из существующих локальных изображений, номером издания, короткой serif-фразой и 3–5 метаданными. Композиция выразительна без motion; вокруг воздух, тонкие линии и маленькая ссылка пропуска. Нет пустого белого прямоугольника, luxury, самолётов, планет и эффектов reader-приложения. Новые stock assets не нужны, пути изображений и copy собраны в отдельном data-объекте.

Первый кадр занимает примерно один viewport, выпуск расположен в центре. Нет particle systems, aggressive drop shadow, glassmorphism, neon, glow или floating 3D interface. Глубина ограничивается тонкой кромкой и мягкой небольшой тенью.

## Scroll journey

Нативная прокрутка, без preventDefault и изменения wheel/touch поведения. Начало почти статичное, без автопроигрывания. Общий путь до исходного hero 1–1.5 высоты viewport, короткая sticky-сцена допустима. Cover при скролле открывается через умеренную перспективу/подъём и поворот, под ним появляется настоящий разворот. Движение медленное сначала, более быстрое в раскрытии, спокойное в конце. Разворот: слева ISSUE 00 / ISTANBUL, «8 PEOPLE / ONE STORY», редакционный заголовок и небольшая фотография; справа большой живой кадр общего стола из исходного hero, caption и координаты. Это эскиз будущей поездки, не выдуманный состоявшийся тур.

К завершению разворот увеличивается, перспектива уходит; повторяются фотография общего стола, текст hero, deep blue и сетка. Переход без белого flash, без смены страницы, без блокирования контента. Не строить реалистичную книгу, flipbook, curled corners, перелистывание кнопками, WebGL, custom cursor, звуки, видео или loading screen. Использовать CSS transform/opacity, scroll-position и requestAnimationFrame, IntersectionObserver для остановки расчётов вне сцены. Новая dependency не требуется.

За 1–2 секунды взгляда на разворот связь «каждая поездка — отдельный Issue» должна читаться по номеру выпуска, городу, людям и короткой фразе; проверить это в статичном кадре отдельно от движения.

## Доступность и состояния

Обычные ссылки #start / открыть выпуск доступны с клавиатуры; видимый focus, семантический section, осмысленные заголовки, alt. Статические/анимированные декоративные повторы разворота не создают повторного доступного контента. Нет focus/scroll traps и обязательного mouse interaction. При отключённом или сломанном JS остаются обложка, anchor и исходный SSR-контент. #start работает при прямом заходе, перезагрузке, клиентской навигации и skip; intro не меняет историю автоматически и не переигрывает при выборе формата/выпуска.

На desktop 1440×900 раскрытие в перспективе; на 1024 подходящий масштаб; на 390×844 обложка крупная, раскрытие проще и более плоское, разворот вертикально, без мелкого текста или горизонтального overflow. Portrait/landscape и resize пересчитывают прогресс без скачка высоты. Reduced motion: красивая статичная обложка, затем обычная страница; без сложного 3D и длинного пустого scroll journey. Контраст текста ≥4.5:1, крупного ≥3:1. Производительность: Next Image с sizes, eager/high fetch priority только первой фотографии; внутренние кадры без лишнего высокого приоритета; локальные шрифты, отсутствие layout shifts; обновление только CSS variables без React rerender на каждый scroll; passive listeners и cleanup.

## Проверка

До реализации записать hashes всех исходных /test файлов, assets, глобальных styles/layout и package files; снять screenshot baseline. После создания копии проверить визуальное/DOM совпадение. После intro проверить /test и /test_2 рядом на 1440×900, 1024px и 390×844; сохранить кадры cover/open/spread/transition/hero и baseline. Сравнить hashes и изображения исходной страницы до/после, а также исходный hero с клоном на #start. Проверить keyboard skip, прямой deep link, reduced motion, JS off, scroll назад, resize, отсутствие overflow, ошибок консоли и сохранение поведения формы/выпусков. Провести отдельный refinement pass после первого визуального просмотра, записать изменения и повторно снять кадры.

Проверки репозитория: frontend unit tests, lint, typecheck, production build, существующие тесты /test и новые браузерные проверки экспериментального поведения. Обновить только frontend Docker service, чтобы оба маршрута были доступны на localhost:3000; не менять backend/БД. Не утверждать smoothness по одному screenshot: снять несколько progress frames и проверить browser measurements, оговорить пределы проверки реального устройства.

## Границы и швы

Одна поверхность: экспериментальный route и scoped-компоненты. Неизменяемый редакционный контент переиспользуется, его дерево копируется для изменения anchors. Animation owns only scene refs/CSS variables; hiding stays within its CSS module. Шов проверки — браузерная публичная страница и её нативные anchors, без экспорта тестовых внутренних функций. API, persistence, auth и pricing вне этой задачи.

## Финальный отчёт

Кратко перечислить реально использованные skills/tools, новые и изменённые файлы, гарантию неизменности baseline, устройство animation, места изменения фотографий/текстов/spread, URL intro и #start, responsive решения и результаты проверок. Отметить только конкретные визуальные решения для обсуждения после просмотра, без построчного описания. Обновить документированную карту проекта в рамках вызванного autopilot workflow, сохранить записи проверки и контрольные точки git без пользовательских незакоммиченных файлов.
