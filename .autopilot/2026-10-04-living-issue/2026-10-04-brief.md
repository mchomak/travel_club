# User brief

[$autopilot](C:\Users\McHomak\\.agents\skills\autopilot\SKILL.md) full
Ты работаешь в существующем проекте Travel Club.
\

\
Контекст проекта, стек и правила репозитория уже известны тебе из AGENTS.md и текущего кода.
\

\
Эта задача — дизайнерский эксперимент.
\

\
Сейчас существует рабочая тестовая версия главной страницы:
\

\
http\://localhost:3000/test
\

\
и её основной контент начинается с anchor:
\

\
http\://localhost:3000/test#start
\

\
Нужно сохранить эту версию как CONTROL / BASELINE и создать рядом экспериментальную версию:
\

\
http\://localhost:3000/test_2
\

\
Главное правило:
\

\
/test НЕ ИЗМЕНЯТЬ.
\

\
/test_2 должен содержать копию текущей страницы /test, но перед существующим контентом необходимо добавить одну сильную фирменную механику:
\

\
LIVING ISSUE.
\

\
Цель — сравнить:
\

\
/test
\
\= базовый editorial landing
\

\
/test_2
\
\= тот же сайт + фирменный opening experience
\

\
Не используй эту задачу как повод снова редизайнить весь сайт.
\

\
\--------------------------------------------------
\
0\. СНАЧАЛА ИЗУЧИ ПРОЕКТ И ДОСТУПНЫЕ SKILLS
\
\--------------------------------------------------
\

\
Перед написанием кода:
\

\
1\. Изучи структуру frontend.
\
2\. Найди реализацию /test.
\
3\. Найди её локальные components, styles, assets и data.
\
4\. Определи всё, что изменение может затронуть глобально.
\
5\. Сделай так, чтобы изменения /test_2 не могли визуально изменить /test.
\

\
Также ДО реализации проверь доступные в текущем окружении Codex skills / skills registry / skill directory.
\

\
Найди и подключи или установи только действительно полезные skills, если среда поддерживает их установку.
\

\
В приоритете навыки/skills, связанные с:
\

\
\- frontend design;
\
\- UI/UX;
\
\- visual design review;
\
\- responsive web design;
\
\- browser automation;
\
\- Playwright / browser screenshots;
\
\- accessibility;
\
\- frontend performance;
\
\- animation / interaction design;
\
\- visual QA.
\

\
Не устанавливай всё подряд.
\

\
Не устанавливай непроверенные случайные skill-паки только потому, что они существуют.
\

\
Цель использования skills — повысить качество арт-дирекшна, визуальной проверки и реализации, а не усложнить проект.
\

\
Если в среде отдельной системы installable skills нет — не блокируй задачу и продолжай с доступными инструментами.
\

\
В финальном отчёте укажи, какие design/frontend skills или инструменты реально использовал.
\

\
\--------------------------------------------------
\
1\. СНАЧАЛА СОЗДАЙ БЕЗОПАСНУЮ КОПИЮ
\
\--------------------------------------------------
\

\
Существующая /test является контрольной версией.
\

\
Не меняй её DOM, CSS, assets, copy или behaviour.
\

\
Создай новую страницу:
\

\
/test_2
\

\
которая до добавления нового opening experience должна визуально и функционально соответствовать текущему /test.
\

\
Очень важно:
\

\
если компоненты /test являются общими с другими страницами и их изменение поменяет /test, не модифицируй их напрямую.
\

\
Для экспериментальной версии допускается создать:
\

\
test_2 page;
\
test_2 components;
\
test_2 scoped styles;
\
test_2 animation logic.
\

\
Immutable assets можно переиспользовать.
\

\
Не создавай ненужное дублирование всей инфраструктуры проекта, но приоритет:
\

\
baseline must remain untouched.
\

\
После создания копии сначала проверь:
\

\
/test работает как раньше;
\

\
/test_2 показывает ту же страницу.
\

\
Только после этого добавляй Living Issue.
\

\
\--------------------------------------------------
\
2\. КОНЦЕПЦИЯ LIVING ISSUE
\
\--------------------------------------------------
\

\
Travel Club строится вокруг идеи:
\

\
TRAVEL CLUB — это живое travel-издание.
\

\
Каждая поездка — отдельный Issue.
\

\
Не просто:
\

\
country → itinerary → purchase
\

\
а:
\

\
ISSUE → PEOPLE → PLACE → STORY → MEMORY.
\

\
Поэтому главной визуальной метафорой должен стать не:
\

\
3D globe;
\
самолёт;
\
карта мира;
\
чемодан;
\

\
а сам ВЫПУСК.
\

\
На /test_2 пользователь должен буквально начать взаимодействие с Travel Club как с новым выпуском digital travel publication.
\

\
Однако это НЕ должна быть реалистичная книга или дешёвый page-flip эффект.
\

\
Нужен contemporary digital editorial object.
\

\
\--------------------------------------------------
\
3\. ОСНОВНОЙ СЦЕНАРИЙ
\
\--------------------------------------------------
\

\
При открытии:
\

\
http\://localhost:3000/test_2
\

\
пользователь сначала видит отдельную opening scene.
\

\
Она занимает примерно один viewport.
\

\
В центре находится цифровой выпуск Travel Club.
\

\
Условная логика обложки:
\

\
TRAVEL CLUB
\

\
LIVING ISSUE
\
EDITION / 01
\

\
PEOPLE
\
PLACES
\
STORIES
\

\
или другая редакционная композиция в существующем визуальном языке сайта.
\

\
Не нужно использовать этот copy буквально.
\

\
Создай арт-директированную обложку, которая выглядит как настоящий independent travel publication.
\

\
Используй существующую цветовую систему страницы:
\

\
off-white;
\
graphite;
\
deep blue;
\
editorial serif;
\
grotesk.
\

\
Можно использовать одну сильную фотографию из уже имеющихся stock assets проекта либо подобрать подходящую.
\

\
Объект должен выглядеть как magazine issue, но без чрезмерного skeuomorphism.
\

\
Не нужны:
\

\
реалистичные кожаные переплёты;
\
толстые 3D страницы;
\
глянцевые эффекты;
\
золотое тиснение;
\
реалистичная симуляция физической книги.
\

\
Это digital editorial object.
\

\
\--------------------------------------------------
\
4\. ПЕРВАЯ ФАЗА — COVER
\
\--------------------------------------------------
\

\
Начальное состояние должно быть почти статичным.
\

\
Пользователь должен успеть понять объект.
\

\
На экране могут присутствовать:
\

\
TRAVEL CLUB masthead;
\

\
edition number;
\

\
issue metadata;
\

\
большое изображение;
\

\
один короткий editorial statement;
\

\
маленький SCROLL TO OPEN / OPEN ISSUE indicator.
\

\
Не перегружай экран.
\

\
Пусть он выглядит как сильная обложка.
\

\
Первое впечатление должно быть:
\

\
«это будто обложка собственного travel-издания».
\

\
\--------------------------------------------------
\
5\. ВТОРАЯ ФАЗА — OPEN
\
\--------------------------------------------------
\

\
При начале прокрутки выпуск начинает открываться.
\

\
Это главная фишка.
\

\
Но эффект должен быть аккуратным.
\

\
Предпочтительная механика:
\

\
cover слегка поднимается / поворачивается в перспективе;
\

\
под ней начинает открываться внутренний spread;
\

\
видна внутренняя editorial композиция;
\

\
camera/viewpoint немного приближается;
\

\
объект занимает больше пространства viewport.
\

\
Используй настоящую 3D perspective только настолько, насколько она повышает ощущение открытия выпуска.
\

\
Например:
\

\
perspective;
\
transform-style: preserve-3d;
\
rotateY / rotateX;
\
translateZ;
\
subtle shadows.
\

\
Но не превращай это в 3D demo.
\

\
\--------------------------------------------------
\
6\. ВНУТРЕННИЙ SPREAD
\
\--------------------------------------------------
\

\
Внутри выпуска не должно быть просто белых страниц.
\

\
Покажи маленький preview мира Travel Club.
\

\
Например один spread может содержать:
\

\
левая сторона:
\

\
ISSUE 00
\
ISTANBUL
\

\
8 PEOPLE
\
ONE STORY
\

\
небольшой editorial headline;
\

\
правая сторона:
\

\
большая живая фотография;
\

\
caption;
\

\
coordinates;
\

\
маленькая secondary photograph.
\

\
Или создай композицию сильнее этой.
\

\
Главная задача:
\

\
за 1–2 секунды пользователь должен понять:
\

\
каждая поездка в Travel Club становится отдельным визуальным Issue.
\

\
\--------------------------------------------------
\
7\. ТРЕТЬЯ ФАЗА — ENTER THE ISSUE
\
\--------------------------------------------------
\

\
При дальнейшем скролле пользователь как будто входит внутрь выпуска.
\

\
Не надо буквально делать эффект «пролёта камеры через бумагу».
\

\
Лучше:
\

\
spread становится крупнее;
\

\
edges журнала уходят за пределы viewport;
\

\
фотография/типографика начинают переходить в layout настоящего сайта;
\

\
3D perspective постепенно исчезает;
\

\
страница превращается в обычную 2D web composition.
\

\
Финальный результат анимации:
\

\
пользователь оказывается у оригинального начала сайта.
\

\
То есть:
\

\
Living Issue
\
↓
\
opening
\
↓
\
spread
\
↓
\
visual transition
\
↓
\
существующий Travel Club hero
\

\
Переход должен ощущаться естественно.
\

\
Не должно быть:
\

\
анимация закончилась →
\
белый flash →
\
совсем другая страница.
\

\
\--------------------------------------------------
\
8\. #start
\
\--------------------------------------------------
\

\
Сохрани anchor:
\

\
\#start
\

\
на начале оригинального клонированного контента.
\

\
Таким образом:
\

\
http\://localhost:3000/test_2
\

\
→ показывает Living Issue intro.
\

\
А:
\

\
http\://localhost:3000/test_2#start
\

\
→ позволяет сразу попасть к обычной версии сайта после интро.
\

\
Это необходимо для:
\

\
\- удобной разработки;
\
\- сравнения;
\
\- deep links;
\
\- возможности позже сделать Skip intro.
\

\
При необходимости добавь на opening scene очень ненавязчивую ссылку:
\

\
SKIP TO SITE
\

\
которая ведёт на:
\

\
\#start
\

\
Но не превращай её в большую кнопку.
\

\
\--------------------------------------------------
\
9\. ДЛИНА ЭФФЕКТА
\
\--------------------------------------------------
\

\
Очень важно не переусердствовать.
\

\
Living Issue должен занимать примерно:
\

\
1–1.5 viewport scroll journey
\

\
до перехода к нормальной странице.
\

\
Не делай intro на 5 экранов.
\

\
Человек пришёл покупать путешествие, а не смотреть интро разработчика.
\

\
Правило:
\

\
WOW moment → быстро → основной сайт.
\

\
\--------------------------------------------------
\
10\. ВИЗУАЛЬНЫЙ ПРИНЦИП
\
\--------------------------------------------------
\

\
Эффект должен соответствовать уже существующему Travel Club.
\

\
НЕ создавай новый visual identity.
\

\
Сохрани:
\

\
\- текущую editorial typography;
\
\- deep blue;
\
\- off-white;
\
\- thin rules;
\
\- Issue numbering;
\
\- metadata;
\
\- coordinates;
\
\- serif / grotesk contrast;
\
\- фотографический стиль текущей страницы.
\

\
Living Issue должен ощущаться так, словно этот объект всегда был частью текущей дизайн-системы.
\

\
\--------------------------------------------------
\
11\. НЕ ДЕЛАЙ БУКВАЛЬНЫЙ FLIPBOOK
\
\--------------------------------------------------
\

\
Очень важно.
\

\
Не реализовывай:
\

\
\- click left/right to turn pages;
\
\- curled paper corners;
\
\- hundreds of book pages;
\
\- realistic PDF viewer;
\
\- page flip sound;
\
\- skeuomorphic digital book.
\

\
Мы не продаём журналы.
\

\
Журнал — это культурная метафора Travel Club.
\

\
Opening должен продолжать сайт, а не превращать его в reader application.
\

\
\--------------------------------------------------
\
12\. MICRO DETAILS
\
\--------------------------------------------------
\

\
Добавь небольшие детали, которые делают opening убедительным.
\

\
Например:
\

\
EDITION / 01
\

\
ISSUE / LIVING
\

\
OCT 2026
\

\
PEOPLE > PLACES
\

\
41°00'N
\

\
TC / EDITORIAL DESK
\

\
PAGE / 001
\

\
небольшой caption.
\

\
Не нужно использовать всё одновременно.
\

\
Выбери 3–5 элементов.
\

\
Лучше мало, но точно.
\

\
\--------------------------------------------------
\
13\. ОБЛОЖКА НЕ ДОЛЖНА БЫТЬ ПУСТОЙ
\
\--------------------------------------------------
\

\
Не делай:
\

\
белый прямоугольник +
\
TRAVEL CLUB по центру.
\

\
Это будет слишком минималистично.
\

\
Обложка должна иметь характер.
\

\
Используй:
\

\
\- сильную editorial image;
\
\- необычный crop;
\
\- большой masthead;
\
\- metadata;
\
\- номер;
\
\- небольшие marginalia;
\
\- хороший typographic tension.
\

\
Вдохновение:
\

\
independent travel publication;
\
culture magazine;
\
city guide;
\
photo essay.
\

\
Не luxury fashion catalogue.
\

\
\--------------------------------------------------
\
14\. ЖИВАЯ, НЕ СТЕРИЛЬНАЯ ФОТОГРАФИЯ
\
\--------------------------------------------------
\

\
Если нужны новые stock assets, выбирай:
\

\
\- candid travel;
\
\- street photography;
\
\- люди;
\
\- вечер;
\
\- общий стол;
\
\- транспорт;
\
\- город;
\
\- motion blur;
\
\- direct flash;
\
\- детали.
\

\
Не:
\

\
\- beach paradise;
\
\- человек с чемоданом;
\
\- самолёт над облаками;
\
\- generic luxury resort.
\

\
Если добавляешь новые изображения:
\

\
положи их локально в scoped test_2 assets, если это возможно.
\

\
Сделай замену фотографий позже простой.
\

\
\--------------------------------------------------
\
15\. АНИМАЦИОННАЯ ТЕХНОЛОГИЯ
\
\--------------------------------------------------
\

\
Сначала изучи существующие dependencies.
\

\
Если в проекте уже установлен качественный motion stack — используй его.
\

\
Например:
\

\
Motion / Framer Motion;
\
GSAP;
\
другая уже имеющаяся библиотека.
\

\
Если подходящей библиотеки нет:
\

\
оцени, можно ли надёжно сделать эффект с:
\

\
CSS transforms;
\
scroll progress;
\
requestAnimationFrame;
\
IntersectionObserver.
\

\
Устанавливай новую animation dependency только если она действительно заметно улучшит:
\

\
\- scroll synchronization;
\
\- stability;
\
\- smoothness;
\
\- maintainability.
\

\
Не добавляй Three.js только ради журнала.
\

\
Для Living Issue полноценный WebGL не должен быть нужен.
\

\
\--------------------------------------------------
\
16\. SCROLL BEHAVIOUR
\
\--------------------------------------------------
\

\
НЕ используй scroll-jacking.
\

\
Пользователь скроллит обычной страницей.
\

\
Animation progress может следовать scroll position.
\

\
Допустим небольшой pinned/sticky scene.
\

\
Например:
\

\
intro container имеет достаточную scroll-height;
\

\
magazine viewport sticky;
\

\
animation рассчитывается по progress.
\

\
Но native scrolling должен оставаться естественным.
\

\
\--------------------------------------------------
\
17\. INTERACTION FEEL
\
\--------------------------------------------------
\

\
Эффект должен ощущаться:
\

\
editorial;
\
tactile;
\
precise;
\
quiet;
\
confident.
\

\
Не:
\

\
game;
\
tech demo;
\
3D configurator;
\
portfolio gimmick.
\

\
Движение:
\

\
медленное в начале;
\

\
чуть быстрее в переходе;
\

\
спокойное завершение.
\

\
Используй хорошую easing curve.
\

\
\--------------------------------------------------
\
18\. SHADOW / DEPTH
\
\--------------------------------------------------
\

\
Поскольку magazine object должен ощущаться физически присутствующим, допускается лёгкая глубина:
\

\
paper edge;
\
subtle shadow;
\
small parallax;
\
perspective.
\

\
Но избегай:
\

\
aggressive drop shadow;
\
glassmorphism;
\
neon;
\
glow;
\
floating 3D interface.
\

\
\--------------------------------------------------
\
19\. ПЕРЕХОД К САЙТУ
\
\--------------------------------------------------
\

\
Это одна из важнейших частей.
\

\
Не допускай ощущения:
\

\
«закончился один сайт и начался другой».
\

\
Последний spread Living Issue должен композиционно подготовить исходный hero.
\

\
Можно использовать:
\

\
общую baseline/grid;
\

\
совпадающую линию;
\

\
совпадающую фотографию;
\

\
повтор headline;
\

\
общий deep blue accent;
\

\
движение masthead.
\

\
Например один объект из magazine spread может визуально продолжиться в первом hero.
\

\
Найди наиболее элегантный вариант самостоятельно.
\

\
\--------------------------------------------------
\
20\. DESKTOP
\
\--------------------------------------------------
\

\
Главный эффект проектируй для desktop:
\

\
1440 × 900
\

\
и похожих экранов.
\

\
Журнал должен иметь красивую пропорцию.
\

\
Не обязательно A4.
\

\
Можно использовать собственный Travel Club format.
\

\
Он должен хорошо занимать viewport и оставлять вокруг достаточно воздуха.
\

\
\--------------------------------------------------
\
21\. MOBILE
\
\--------------------------------------------------
\

\
Не пытайся буквально повторить desktop 3D opening на телефоне, если это выглядит плохо.
