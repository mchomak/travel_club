# Спецификация: Travel Club /test

## Задача
Первая полноценная арт-дирекция публичной главной: живое travel-издание с ясными услугами и началом разговора. Локальная экспериментальная версия, которую можно развивать. Все 59 требований манифеста входят в один проход.

## Изоляция
Next.js App Router. Новый маршрут вне группы (public), собственные компоненты и CSS Module. Не менять /, root layout, global CSS, admin, конструктор, API, auth, БД, зависимости. Проверены package.json, routing, глобальные стили и Docker. Общие admin компоненты не подходят визуально; используем React, next/image и уже доступные средства. Тяжёлых эффектов нет.

## Арт-дирекция
Современный журнал о людях и поездках. Off-white #f3f2ee, graphite #20211f, ink navy #142d51, muted #61615c, burgundy #713b43 для Стамбула. Крупный современный grotesk с кириллицей (Golos Text или Manrope); выразительный умеренный serif с кириллицей (Lora). Локальные WOFF2, font-display swap, централизованные tokens. Sans для ясности, serif для эмоционального высказывания. Desktop 12-column grid, асимметричный hero: крупный headline слева и живое фото справа с номером выпуска. Ясное позиционирование и три равноправные услуги в первом экране или на его границе. Редакционные входы, без иконок и SaaS карточек. Небольшие подписи, крупная типографика, прямые линии, функциональные ссылки. Ни luxury, ни декоративной технологичности.

## Первый экран
Навигация по странице, слово Travel Club, тезис «Куда — важно. С кем — важнее.», короткое объяснение трёх форматов. Действия: начать разговор / смотреть выпуски. Три услуги с номером, коротким именем, объяснением и ссылкой к форме. Mobile: компактное меню без скрытых недоступных действий, headline и фото имеют самостоятельный ритм.

## Заявка
Непосредственно под hero/продуктовыми входами — компактный «Start your story». Radio/segmented control на три услуги; destination, when, contact. Продуктовый вход выбирает формат и ведёт к форме. Без новых endpoint. Типизированный submit-адаптер возвращает демонстрационный результат без отправки/хранения. Явная пометка демонстрационной формы до отправки и честный success state «В этой версии данные не отправляются». После успеха можно начать снова. Обязательны формат и контакт; destination и when допускают «не знаю» / «пока не решил». Пустые/невалидные значения дают inline errors, aria-invalid, aria-describedby, focus первого ошибочного поля. Поддержать email, телефон и Telegram (username/URL), различая минимум реального формата от произвольного текста. Поля не теряются при ошибке; submit блокируется на время обработки; ошибка адаптера даёт повторить.

## Выпуски
Data-driven Issue Archive: ISSUE 00 / ISTANBUL, ISSUE 01 / SHANGHAI, NEXT ISSUE / UNKNOWN. Это образцы, не реальный архив туров. Явная надпись «Концептуальные выпуски · ...» рядом с блоком. Каждый вариант имеет destination, sample date, people, mood, hero/detail image и theme {background, foreground, accent}. Кнопки переключателя с aria-pressed; клавиатура и focus работают. React state меняет только блок архива, CSS variables задают палитру, transition 250–450ms. Стамбул — ivory/burgundy/tobacco, Шанхай — graphite/cobalt/silver, NEXT — базовый navy/milk. Выбранное фото, история и метаданные также меняются. Next не изображает открытую продажу. Небольшая запоминающаяся этикетка next issue со статусом «В разработке», unknown destination/date, ориентир компании 6–9 как концепция, не количество мест.

## Содержание
После архива — Next Issue bridge и «Узнать первым», которое выбирает group и ведёт к форме. 3–4 принципа (People > Places; Curated, not crowded; Good taste ≠ Luxury; The story stays), коротко и редакционно. Memory section: контролируемая композиция 2–3 candid фото, билет/чек, timestamp, координаты и короткая авторская заметка как пример будущей книги. Не выдавать цитату за реальный отзыв. «8 people / 7 days / 1 story» только sample макета. Club объясняет, что знакомство продолжается после поездки, и отмечает ранний доступ/встречи как направление развития, без обещаний готовой системы. Спокойный рабочий процесс, 4 шага, раскрывающий результат каждого из трёх продуктов: маршрут передаётся для самостоятельной поездки; turnkey координируется; group с сопровождающим. Минимальные условия: обсуждение до оплаты, фиксированный состав, прозрачный бюджет — принципы, без юридических выдумок. Финальное «С чего начнётся ваша следующая история?» и CTA к форме.

## Footer
Travel Club, copyright 2026, Telegram / Instagram / контакт как честные placeholders с «скоро» или доступной панелью пояснения; не href="#" и не fake адрес. Условия/документы — доступное пояснение что будут добавлены, без изобретённых legal facts. Контакт для обсуждения — текущая форма с demo-пометкой.

## Контент
Небольшие типизированные массивы navigation, products, issues, principles; issue themes данные. Тексты русского продукта понятны, английский — короткие metadata. Короткий спокойный copy без travel clichés. Изображения и fonts в public/test. README с источником, автором, лицензией, размерами; замена собственными файлами и единые ключи в data. Не придумывать цены, контакты, реальные даты поездок, продажи, лицензии.

## Медиа
Royalty-free stock Pexels/Unsplash. Отдавать локально: people at table/street/night/transport и городские кадры. Hero приоритетный, остальные lazy, next/image с sizes и явными размерами. Оптимизированные фото ~1200–1600px, разумный общий размер. WOFF2 с кириллицей и Latin, без сетевой загрузки шрифтов во время build. Фотографии — иллюстрации, не Travel Club participants.

## Доступность
Semantic main/section/nav/footer, heading hierarchy, настоящие links/buttons; radio/fieldset/legend для формата, видимые labels, alt фото, skip link, чёткий focus, контраст 4.5:1 текста и 3:1 large. Reduced motion отключает переходы/scroll анимации. Контент виден без IntersectionObserver, никаких reveal gating, scroll-jacking и WebGL. Тема архива не меняет контраст остальной страницы.

## Границы и швы
Один изолированный frontend surface. Контент владеет редакционными данными и theme tokens; страница владеет выбранным Issue и навигацией; форма владеет полями/validation/success и наружу отдаёт typed submit-adapter. Проверять поведение через браузер и public submit boundary. Реальное API — вне scope.

## Проверка
Запуск localhost:3000/test через пересборку только frontend Docker; development preview можно 3001. lint, typecheck, production build, existing unit suite. Браузер: выбор выпуска меняет палитру/фото, keyboard/focus/radio, валидация и demo success, CTA предвыбирает формат, честные placeholders. Скриншоты и overflow на 1440×900, 1024px, 390×844, refinement pass по реальным screenshots. Smoke /, /tours, /services/route, /services/turnkey, /payment, /admin/login и unauthenticated admin redirect. Не менять и не проверять business data через destructive действия. Финал: созданные файлы и центральные места контента/фото/colors; результаты и ограничения проверок.

## Вне рамок
Backend, CMS, database, auth, payment, отдельные destination pages, community functionality, deployment наружу. Никакие запросы исходного брифа не сняты.

## Решения полного автомата
Нейтральные контакты и документы остаются placeholders. Форма demo, API подключается через adapter. Выпуски — концептуальные. Страница временно использует локальный stock и заменяемую шрифтовую пару. T0, один цельный проход; реализация делегируется одному свежему контексту, обзор и QA выполняются отдельно, чтобы сохранить внимание к 38 разделам брифа. Это явная адаптация процесса T0, без дробления продукта на таски.

G2: независимый читатель проверил исходные 38 разделов пользователя непосредственно из сообщения против этой спецификации, без манифеста; расхождений нет. Пока дословная копия брифа сохранялась отдельным агентом, источником проверки служило оригинальное сообщение. Это явная адаптация формы передачи исходника, требования не сокращены.
