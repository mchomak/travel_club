# 01 — Смена пароля администратора

**Требования:** R08, A01 → R08
**Blocked by:** нет
**Зона:** `backend/app/auth.py`, `backend/app/schemas.py`, `backend/tests/`, `frontend/src/app/admin/(private)/account/`, `frontend/src/app/admin/(private)/layout.tsx`, `frontend/src/lib/api.ts`, целевые frontend tests
**Волна:** 1
**Status:** ready

## Что должно заработать

Администратор входит с одноразовым паролем bootstrap, открывает закрытую страницу аккаунта и меняет пароль, подтвердив текущий. Backend проверяет текущий пароль, безопасно сохраняет Argon2-хэш и завершает остальные сессии этого пользователя. В текущем браузере вход сохраняется.

## Из брифа, дословно

> «поставь там логин и пароль, и напиши их мне в чат, я потом поменяю.»

## Разделы спецификации

История 14, Поведение и ошибки, границы `backend/app/auth.py` и страницы аккаунта.

## Критерии приёмки

- [ ] `POST /api/auth/password` доступен только аутентифицированному админу и соблюдает существующую CSRF-защиту.
- [ ] Неверный текущий пароль и невалидная длина нового (12–1024) возвращают понятную ошибку и не меняют хэш/сессии.
- [ ] Успешная смена сохраняет Argon2-хэш, оставляет текущую сессию, удаляет остальные сессии; изменения выполняются транзакционно.
- [ ] `/admin/account` связан с навигацией, форма доступна с клавиатуры, показывает успех/ошибку и очищает чувствительное поле текущего пароля.
- [ ] Backend и frontend tests покрывают успех, неправильный текущий пароль, unauthenticated и валидацию формы; релевантные lint/type checks проходят.

## Ограничения исполнения

Не создавать учетные данные и не менять bootstrap/пользователей БД. Не добавлять зависимостей. Не создавать commit.
