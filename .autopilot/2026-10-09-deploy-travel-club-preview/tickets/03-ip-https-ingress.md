# 03 — HTTPS по IP на свободном порту

**Требования:** R01, R03, R04, R05, R07, R09
**Blocked by:** нет
**Зона:** `deploy/nginx/`, `deploy/certbot/`, `docs/deployment-preview.md`
**Волна:** 1
**Status:** ready

## Что должно заработать

Хостовый Nginx отдаёт ACME webroot challenge на свободном TCP/80 и проксирует весь публичный сайт по HTTPS на проверенный свободный порт (8443, 9443 или 10443). Сертификат Let's Encrypt содержит IP в SAN, обновляется автоматически и reload-ится без остановки VPN или Telegram-бота. Документация содержит упорядоченные безопасные команды для применения после успешного единого push.

## Из брифа, дословно

> «занять другой порт, а не 443 и настрить на него https доступ, ссылка пока будет без домена чисто по ip и порту»
> «на сервер арбоатет VPN и еще telegam бот не сломай их, проверяй какие ты порты используешь.»

## Критерии приёмки

- [ ] Nginx webroot-конфиг обрабатывает ACME на TCP/80; неизвестные пути не раскрывают файлы и обычный HTTP переводит на HTTPS-порт параметром.
- [ ] TLS-конфиг-шаблон получает подтверждённый IP и выбранный свободный порт, проксирует на loopback frontend и не содержит сертификатных ключей.
- [ ] Runbook требует проверить порты/ресурсы/контейнеры до изменений, не трогать владельца занятого порта и остановиться при занятом TCP/80 без безопасного пути или недоступном внешнем порте.
- [ ] В runbook проверяется Certbot ≥5.4, используется IP + `shortlived` + `webroot` (не nginx plugin), сначала staging; при провале issuance деплой останавливается.
- [ ] Автоматическое renewal запускается чаще срока сертификата и применяет deploy-hook `systemctl reload nginx`; проверяются timer и `certbot renew --dry-run`.
- [ ] Runbook делает commit/push `origin/main` до SSH-изменений, содержит запуск bootstrap после здоровой БД/миграций и post-deploy smoke/resource checks; никакие пароли не попадают в файл или shell history.

## Ограничения исполнения

Не подключаться к серверу и не выполнять deploy. Не устанавливать Certbot/Nginx на рабочую машину. Не создавать commit.
