# Спецификация: публикация Travel Club на VPS

## Задача

Нужно получить рабочую публичную ссылку на сайт и закрытый конструктор поездок, сохранив VPN и Telegram-бота на том же сервере. Кроме запуска, нужен способ сменить начальный пароль администратора.

## Решение

Развернуть приложение отдельным Compose-проектом в `/opt/travel_club`: Next.js frontend, FastAPI backend и собственный PostgreSQL volume. До изменений повторно проверить ресурсы хоста, слушающие порты и все существующие контейнеры. Если TCP/80 свободен, Nginx обслуживает на нём ACME HTTP-01; если он занят, не останавливать и не менять владельца порта — продолжать только при возможности безопасно добавить webroot challenge без изменения текущего поведения, иначе остановиться и сообщить причину. Для HTTPS выбрать свободный и доступный извне TCP-порт: сначала 8443, при занятости или блокировке — следующий заранее проверенный порт из 9443 и 10443. HTTPS проксирует frontend на loopback. Использовать IP-сертификат Let’s Encrypt профиля `shortlived` с автоматическим продлением. Оставить VPN на 443 и Telegram-бота на найденном при повторной проверке порту. Собрать frontend и backend images локально под архитектуру VPS и передать их серверу, чтобы не собирать приложение на малом VPS.

## Проверка ресурсов

Перед деплоем зафиксировать CPU, доступную RAM, swap, занятое место, текущую нагрузку, контейнеры и их расход памяти; после запуска повторить замеры и проверить состояние/перезапуски контейнеров и kernel OOM. Сайт считается подходящим для небольшой демонстрационной нагрузки, если после прогрева все три новых сервиса healthy, существующие контейнеры остаются запущены, не было OOM или новых рестартов, остаётся не менее 300 MiB доступной памяти и не менее 3 GiB свободного диска. Если условие не выполнено, не создавать администратора и безопасно остановить только проект `travel_club`; сообщить измерения и что потребуется для увеличения ресурсов.

Ранее выполненный read-only снимок сервера `31.57.143.12`, указанного пользователем в SSH-адресе: Ubuntu 24.04.5 x86_64, 2 vCPU, 2 GiB RAM, диск 58 GiB (примерно 52 GiB свободно), около 907 MiB доступной памяти, swap отсутствует. Значения являются предыдущим наблюдением, не обещанием ресурсов; повторить все замеры перед запуском.

## Git и полный охват общего коммита

Включить весь tracked/untracked diff, существовавший в рабочем дереве на старте задачи, плюс необходимые изменения этой задачи, одним commit. Исключить только `.env`, фактические секреты и игнорируемые машинные PID/log-файлы. Сначала проверить staged diff и secret scan; затем commit и push `origin/main`. Если push не завершился успешно, удалённый deploy не начинать.

Из-за требования одного общего commit исполнители оставляют код незакоммиченным; после ревью всех тасков orchestrator выполняет один aggregate commit без переписывания истории.

## Поведение и ошибки

- Публичные editorial-страницы и demo-формы остаются публичными. `/admin/*` и защищённые API требуют действующую сессию; регистрации нет.
- Nginx принимает только public ingress для frontend; PostgreSQL и API остаются внутри Docker/loopback. Успешный `/api/health` доступен через внутреннюю проверку backend, но DB-порт не публикуется наружу.
- Изменение пароля доступно только из авторизованного кабинета. JSON-запрос проходит существующую CSRF-защиту (`X-Requested-With` и `Origin`). Текущий пароль сверяется Argon2; новый пароль требует 12–1024 знаков. На неверный пароль UI показывает понятную ошибку и сохраняет введённый новый пароль, но очищает поле текущего.
- Обновление пароля коммитится транзакционно; при ошибке базы старый пароль продолжает работать. После успеха очищается форма и показывается подтверждение.
- Для защиты от утечек начальный пароль не включать в аргументы команд, shell history, файлы репозитория или вывод проверок; интерактивный `getpass` скрипта bootstrap не должен его печатать.
- До запуска повторно подтвердить адрес сервера из пользовательского SSH-адреса, текущих владельцев 443 и порта Telegram-бота, архитектуру, ресурсы и свободное место; предыдущая проверка — ориентир, а не замена свежему снимку. Если TCP/80 занят и нельзя безопасно обслужить только challenge, или ни один проверенный HTTPS-порт извне не доступен — не менять существующие службы и сообщить сетевой блокер.
- Сертификат запрашивать только после проверки версии Certbot ≥5.4 и успешной staging-проверки IP через `webroot`; Nginx/Apache Certbot installer для IP не использовать. Если staging-проверка или выдача доверенного сертификата не проходит, не запрашивать администратора, не переходить на self-signed сертификат и остановиться с причиной. При блокировке входящего HTTP-01 исправлять только firewall для свободного TCP/80, не затрагивая `443` или текущие сервисы.
- Nginx конфиг проверять перед reload. Compose запускать только как отдельный проект `travel_club`; не использовать `down -v`.

## Решения по реализации

- Использовать source-free deployment Compose с tagged frontend/backend images; передать оба image на VPS после локальной сборки. Задать `APP_ENV=production`, `COOKIE_SECURE=true` и `ALLOWED_ORIGIN` из фактически подтверждённого SSH-IP и выбранного внешне доступного порта (не хранить текущие адрес и порт в коде приложения).
- Исправить маркер в `.env.example`, чтобы `scripts/init_env.py` действительно заменял его новым случайным значением, а не копировал общий примерный пароль.
- Создать пароль базы на сервере через существующий `scripts/init_env.py`, локальный `.env` не публиковать.
- Установить/использовать Nginx и Certbot из доверенных репозиториев; версия Certbot ≥5.4 должна поддерживать IP identifier, профиль `shortlived` и webroot renewal. Не использовать Nginx/Apache installer plugin: публичная IP-поддержка для запроса сертификата идёт через webroot.
- Логин начальной учётной записи принять `traveladmin`; если имя уже занято, не перезаписывать существующего пользователя, выбрать уникальный суффикс.
- ASSUMPTION — демонстрационная нагрузка небольшая; пороги для проверки ресурсов выбраны как операционные защитные условия, потому что ожидаемое число одновременных посетителей не задано.
- Сборки и существующие статические asset-замены отдать как часть коммита согласно просьбе о едином коммите; перед commit выполнить secret scan и исключить машинные `.env` и локальные логи.
- После запуска проверить TLS с валидацией сертификата, публичный frontend, защищённость admin/API, здоровье трёх Compose-сервисов, renewal timer и что исходные VPN/бот контейнеры остались Up.
