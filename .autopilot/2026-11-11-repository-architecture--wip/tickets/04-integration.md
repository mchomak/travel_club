# 04 — Интеграция и очистка
**Требования:** R01–R03, R16–R53, R59–R78, R83–R85, R89, R104–R116, R122–R173, R241–R264, G02, G03.
**Зона:** корневые конфигурации, `frontend/`, инфраструктура, backend CSRF-конфигурация и её тесты, тесты интеграции.
**Волна:** 2; **Blocked by:** 01, 02, 03

> «Общий адрес с маршрутизацией к трём приложениям»
> «Не удаляй общие ресурсы»

Интегрировать три готовых приложения, root npm команды, общий origin и cookie, корректную маршрутизацию Next статики и assets, env и локальный Compose без изменения существующих данных; backend и миграции оставить едиными. Сверить существующие URL и тесты, архивировать и удалить только подтверждённо неиспользуемый старый frontend. Тег и описание release уже созданы локально; запрещено отправлять их с CustDev. Нет force push, reset, удаления баз или публикации.

Прямые dev-origin Constructor и Interviews и общий gateway должны авторизованно работать с API; существующий CSRF проверяет точные origins, а не только CORS. При необходимости добавь совместимый явный список дополнительных origins с проверкой по точному совпадению, тестами положительных и запрещённых origins; не ослабляй проверку и не меняй API-контракты.

Учесть `/admin/login?next=/research`, host-only cookie, `/_next/image` либо namespaced image optimizer Website, `HOSTNAME=0.0.0.0` для Interviews внутри контейнера и сборочные `NEXT_PUBLIC_*_URL` для общего origin. Сохранять оригинальный Host, Origin, Cookie, Set-Cookie, Location, query и тела запросов; не менять named volume PostgreSQL. Результаты текущей разведки маршрутизатора см. в сообщении координатора, факты перепроверять в коде.

Приёмка: независимый запуск и build каждого, работа общего origin, auth и API, 404 legacy URLs, отсутствие битых внутренних ссылок и общих visual imports. Сначала проверить, что перемещённые файлы и необходимые assets сохранены.
