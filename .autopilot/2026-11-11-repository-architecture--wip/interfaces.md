# Границы и правила

- Website владеет собственными страницами, визуальными компонентами, токенами, шрифтами и ресурсами; существующие публичные URL сохраняются, типографика — Lato утверждённой системы.
- Constructor владеет `/admin/**`, защищённым каталогом `/home`, собственной визуальной системой и интерфейсом поездок; использует существующие API и auth.
- Interviews владеет `/research/**`, собственной визуальной системой и экраном интервью; использует существующие API и auth.
- Backend, PostgreSQL, миграции и бизнес-правила остаются едиными. Никаких межпродуктовых визуальных импортов.
- В общем origin маршруты `/admin/**`, `/home` идут Constructor, `/research/**` — Interviews, `/api/**` — backend, прочие — Website. Cookie и безопасность сохраняются. Статика приложений должна иметь непересекающиеся URL.
- При самостоятельном доступе к private frontend на разных портах POST-запросы должны проходить строгую проверку CSRF origin в backend. Существующие `ALLOWED_ORIGIN` и `RESEARCH_ORIGIN` покрывают только два адреса: интеграция должна обеспечить и gateway, и оба прямых адреса явным allowlist без ослабления проверок, с тестами и документацией.
- Каждый frontend собирается и запускается самостоятельно; отдельно требуется интеграция общего origin. Существующий стек и версии пакетов не обновлять.
- Текущий исходный код — `frontend/`; пользоваться им read-only, пока три приложения строятся параллельно. Работники меняют только собственные `apps/<имя>`; не редактируют друг друга, `frontend/`, backend или корневую конфигурацию. Не удалять файлы, пользовательские данные или тег.
- Windows: `npm.cmd run lint`, `npm.cmd run typecheck`, `npm.cmd test -- --run --testTimeout=15000`, `npm.cmd run build`; одиночный тест через `npm.cmd test -- <path>`. Нет внешних установок или секретов без необходимости.
- Архивный тег локален: в нём содержатся материалы CustDev, которые пользователь запретил публиковать. Не отправлять тег и не создавать публичный Release этого снимка.
