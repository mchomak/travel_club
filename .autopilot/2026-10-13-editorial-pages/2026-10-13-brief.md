# Изначальная задача

> Записано 2026-10-13. Неизменяемый текст брифа.

Работай в существующем проекте Travel Club.

КОНТЕКСТ

Сейчас основной актуальный экспериментальный homepage находится на:

http://localhost:3000/test_5

Его визуальный язык, композиционный характер и общая концепция являются текущей базой для следующих страниц сайта.

Также в проекте уже должен существовать Design System Playground / design tokens или связанные с ним стили. Сначала изучи текущую реализацию и переиспользуй её там, где это разумно.

ЗАДАЧА

Нужно создать следующие базовые страницы:

/formats
/archive
/start
/thanks

а также юридический раздел:

/legal
/privacy
/personal-data

и branded 404 page через стандартный механизм текущего Next.js router.

После этого связать новые страницы с текущей homepage /test_5:

- существующие релевантные ссылки / CTA на /test_5 должны вести на новые страницы;
- на всех новых страницах должна быть очевидная возможность вернуться на homepage;
- навигация между страницами должна быть рабочей.

Это пока НЕ финальные production-страницы.

Главная задача этапа:
создать качественный архитектурный и визуальный каркас, который потом можно будет легко корректировать после финального выбора typography, colors и spacing.

4. Не переписывай /test_5 без необходимости.

5. Не трогай backend, database, admin, constructor и unrelated routes.

2. ГЛАВНЫЙ ТЕХНИЧЕСКИЙ ПРИНЦИП ДИЗАЙН-СИСТЕМЫ

==================================================
3. АРХИТЕКТУРА TYPOGRAPHY
==================================================

Используй трёхуровневую модель.

LEVEL 1 — BASE / PRIMITIVE TOKENS

Например:

--tc-font-serif
--tc-font-sans

--tc-font-weight-regular
--tc-font-weight-medium

--tc-color-cloud
--tc-color-ink
--tc-color-blue

и т.д.

LEVEL 2 — SEMANTIC TYPOGRAPHY

Например:

--tc-type-display-xl-size
--tc-type-display-xl-line-height
--tc-type-display-xl-spacing

--tc-type-display-size
--tc-type-display-line-height

--tc-type-h1-size
--tc-type-h1-line-height

--tc-type-h2-size
--tc-type-h2-line-height

--tc-type-lead-size
--tc-type-body-size
--tc-type-small-size
--tc-type-meta-size
--tc-type-caption-size

Не обязательно использовать именно эти названия.
Адаптируй naming к текущему проекту.

Главное:
страницы должны использовать семантические роли, а не собственные случайные размеры.

LEVEL 3 — OPTIONAL PAGE OVERRIDES

Иногда конкретной странице может понадобиться небольшое отличие.

Например:

Archive может иметь чуть другой display scale.

Formats может иметь более компактный product title.

В таком случае допускаются scoped aliases / overrides.

Концептуально:

.page-archive {
    --page-display-size: var(--tc-type-display-xl-size);
}

или:

--archive-title-size
--formats-product-title-size

НО:

не создавай полный отдельный набор typography variables для каждой страницы.

80–90% typography должны оставаться глобальными.

Page overrides нужны только для осознанных исключений.

==================================================
5. RESPONSIVE TYPOGRAPHY
==================================================

Typography должна централизованно поддерживать минимум:

desktop
mobile

и tablet, если он уже используется системой.

Предпочтительно через:

clamp()

или централизованные media queries.

Не дублируй responsive typography в каждом page component.

Цель:

если позже я изменю:

H1 96px → 88px

или:

serif A → serif B

из одного design system файла,

изменение должно автоматически распространиться на все соответствующие страницы.

==================================================

- обычное турагентство;
- generic corporate website;
- luxury resort site.

7. CREATIVE FREEDOM
==================================================

На этих страницах у тебя есть больше визуальной свободы.

Если видишь хорошую идею:

- необычная editorial composition;
- scroll detail;

- sticky metadata;
- horizontal editorial element;
- subtle page transition;
- archival indexing;

НО соблюдай правила:

1. Сайт должен хорошо выглядеть на статичном screenshot без анимации.
2. Art direction важнее motion.
3. Максимум одна заметная механика на страницу.
4. Motion не должен мешать чтению.
5. Не добавляй WebGL / Three.js / тяжёлые библиотеки без серьёзной причины.
6. Не делай эффекты только потому, что можешь.
7. Не копируй Living Issue animation с homepage на остальные страницы.
8. Каждая страница может иметь собственный характер, но должна оставаться Travel Club.

Если идея сомнительная:
лучше сделать subtle implementation, чем сложный эффект.

ЧТО ВАМ НУЖНО?
