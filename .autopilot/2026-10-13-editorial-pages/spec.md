# Спецификация: редакционные страницы Travel Club

## Задача и решение
Из одной экспериментальной homepage создать цельный публичный каркас: `/formats`, `/archive`, `/start`, `/thanks`, `/legal`, `/privacy`, `/personal-data`, стандартная branded 404. Главная остаётся `/test_5`. Это не production запуск; персональные данные не передаются и не сохраняются, документы не выдумываются.

## Истории и приёмка
- Общая оболочка: логотип ведёт на `/test_5`, навигация «Форматы / Архив / Начать историю», footer дополнительно содержит все юридические ссылки и © 2026. Никаких новых социальных контактов.
- Formats: три продукта. Маршрут — индивидуальная программа, районы, логистика, места, культура, рекомендации, ориентировочный бюджет; клиент сам бронирует и оплачивает поставщиков. Под ключ — проектирование, подготовка и координация с согласованием состава услуги, без обещаний бронирования/оплаты/юридических гарантий. В компании — ориентир 6–9 человек, общий маршрут и сопровождающий. Для каждого: что получает клиент, как работает, кому подходит; labels GIVE ME THE PLAN / TAKE CARE OF IT / I WANT IN. CTA `/start?format=route|complete|group`. Четыре шага: знакомимся, проектируем, согласуем, отправляемся; финальный CTA.
- Archive: хронология 2026 и 2025, асимметричный фотоиндекс, без одинаковых карточек. Thailand ’26: ISLANDS → BANGKOK / 4 PEOPLE. China ’26: BEIJING → SHANGHAI / 4 FRIENDS + 2 LOCAL FRIENDS IN BEIJING. Явно реальные поездки друзей до публичного клуба, FIELD NOTE, не коммерческие Issues/туры. China ’25 / Madagascar ’25 / Thailand ’25 используют только уже имеющиеся сведения. Тип данных различает field-note и issue с optional detail href, позволяет будущие официальные завершённые поездки, но не добавляет выдуманный Shanghai 2027. Если detail routes не найдены — текстовые записи, не disabled fake links. Иллюстративные фотографии явно отмечены.
- Start: «Начнём с разговора», можно без точного плана. Сначала выбор формата, затем destination, when, participants, optional budget, comment, contact. Contact допускает Telegram/phone/email по существующей валидации. Ограничения длины и положительное целое участников; контакт обязателен, остальные поля дают возможность неопределённости. Ошибки понятные, фокус на первом ошибочном поле. Query выбирает формат; invalid query даёт безопасное значение route. После корректной демонстрации перейти `/thanks`, не передавать поля в URL, localStorage, network или backend. Явное предупреждение перед submit. Не требовать согласия с несуществующим юридическим документом.
- Thanks: честно сообщает о завершении демонстрации и отсутствии отправки/сохранения, не «заявка получена». CTA домой и в архив, минимум информации.
- Legal: hub документов, реальные ссылки privacy/personal-data, статус подготовки. Будущие оферта/реквизиты/договор/оплата и возврат только как будущие документы без содержания.
- Privacy/personal-data: единый читаемый legal template, metadata и юридическая навигация, статус «Документ находится в подготовке. Не является действующим документом». План разделов общей политики и обработки данных без любых правовых утверждений, выдуманных сроков/оператора/контактов. Если действующий текст найден — переиспользовать; проверка показывает, что его нет.
- 404: App Router root `not-found.tsx`, «Этой страницы нет в маршруте», домой и архив, общая оболочка, функциональность стандартной неизвестной страницы и HTTP 404.
- Homepage: только смысловые изменения href/navigation и conversion существующих документных navigation elements в ссылки. Primary CTA → /start, product CTA с context, Форматы → /formats, Архив → /archive, Документы → /legal. Сохранить якоря настоящего содержания, top/back/Field Notes, форму и её state, Living Issue, визуальные стили, тексты, photo editor. Содержание «Ваша история» направить на /start. Обновить только навигационные regression assertions при необходимости.

## Общая система и дизайн
Существующий immutable BASE_TOKENS Playground — источник цветов, типографических размеров/начертаний/line heights/tracking, spacing, layout и ratios. Добавить public adapter: primitives serif/sans/weights/color; semantic role CSS variables h1/h2/h3/lead/body/small/meta/caption/button; central responsive resolution через clamp (desktop/mobile) в rem. Новые страницы получают scoped variables на одной SiteShell, без применения Playground live variables или localStorage draft глобально, без изменения Playground. Основные editorial заголовки serif через централизованный semantic alias, остальное Sans; изменение family, h1/body размера или Cloud в одном источнике/adapter влияет на все новые страницы. Не копировать значения в page CSS. Page overrides, если нужны, только централизованные inherited aliases (архивный год displayXL, product title h2), не отдельные полные системы.

Один shared CSS module для композиции, typography и UI, локальные @font-face с имеющимися файлами (без изменения глобальных CSS). Grid/container max width и paddings из токенов. Fixed-ratio overflow-hidden responsive images с object-fit cover, существующие stock иллюстрации, без новых assets. Formats — продуктовые журнальные развороты с небольшими изображениями; Archive — годовые маркеры и разные масштабы фото; Start — функциональная светлая форма с редакционной side note; Thanks/404 — крупный знак и краткий текст; Legal — узкая читаемая колонка. Без rounded SaaS cards. Только subtle hover из CSS; никаких новых animation/dependency, copy Living Issue, cursor, WebGL или scroll-jacking. Русский основной текст, English только metadata, без рекламных клише. Статический вид уже закончен.

## Границы и швы
- Public tokens adapter владеет отображением BASE_TOKENS в scoped CSS vars; export `createSiteVariables(tokens = BASE_TOKENS)`. Не меняет исходные tokens и Playground.
- SiteShell владеет header/footer/skip link/main и локальной темой, export SiteShell/EditorialLabel/PageIntro/CTA/EditorialImage/LegalNavigation/LegalDocument. Внутренние стили скрыты.
- Контент страниц владеет copy, archive records и format list, рендер через общие primitives; нет backend.
- StartForm владеет transient form state, query input и validation; использует существующую contact validation. Никакого реального submit API.
- Homepage navigation изменяет только href/links в локальных test_5 файлах.
Тестовый шов: Playwright реальные маршруты + минимальные unit tests валидации формы/adapter только при необходимости. Проверить propagation переменных на реальные DOM роли, не просто сравнение объекта с самим собой.

## QA
Lint, typecheck, Vitest, production build. Запустить frontend по localhost:3000 (Docker only frontend rebuild) и проверить на production. Playwright: все новые страницы 1440/1280/768/390, screenshots + визуальный осмотр каждой, no overflow/broken images/console errors, все внутренние nav destinations и anchors, возврат домой, keyboard/visible focus, validation/no network or persistence, query context, unknown URL 404, reduced motion, long legal headings. Проверить propagation serif/H1/body/Cloud через один набор scoped variables на всех страницах. Регрессии test_5 camera/photo-editor и Design System с сохранёнными пользовательскими изменениями. Отдельный refinement pass после визуального осмотра, зафиксировать изменения.

## Вне scope
Backend/admin/database/constructor, homepage copy/layout/Living Issue/Field Notes/Design System Playground, unrelated routes. Не создавать /about /club /events /journal /move /trips или detail pages. Без реальной отправки, DB, production deployment, юридических документов от себя, новых пакетов и stock фото.

## Открытые места
Юридические тексты не предоставлены — подготовленные templates с честным статусом. Detail pages всех архивных destinations отсутствуют — ссылки не создавать. Форма prototype — интеграция следующим этапом по явному запросу.

- Режим full, самостоятельно выполнить бриф до работающего и проверенного результата, без рутинных вопросов. Перед product code изучить структуру, global styles, font imports, typography/colors/spacing/grid/container, header/footer, buttons/links/forms/image components и animation utilities текущей test_5 и Playground; определить повторно используемые BASE_TOKENS, локальные fonts, contact validation, assets, CSS motion. - Сопровождение групп — существующее описание продукта в test_5/data.ts и durable project context, не новая функция или юридическое обещание. Дополнительных capabilities сверх брифа не добавляется.

## D01 — нативная отправка без JavaScript
Финальная privacy-проверка доказала, что React onSubmit не блокирует обычный HTML GET при выключенном JavaScript: контакт попадает в URL. Запрос теста перехвачен до передачи, использованы только dummy данные. Это та же гарантия prototype без передачи данных, не новая возможность. SSR и фаза до hydration должны блокировать submit (click и Enter), после hydration сохраняется обычная client validation → /thanks. При отключённом JavaScript показывается понятная инструкция. Browser regression проверяет отсутствие GET/POST с персональными полями в обоих режимах.
