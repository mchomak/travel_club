## Что должно заработать

Существующие API и формы уже работают; их тесты должны ломаться при потере любого нового поля или при нарушении подтверждения сокращения дат. Усиль проверки результата через публичный ответ API и callback форм.

## Из брифа, дословно

> «для каждого дня статус»
> «сразу выбираем день заезда и время заселения, и день выезда и выселения»
> «необязательное поле с ссылкой»

## Разделы спецификации

Истории 5–7, 12–14, 21–23, 26.

## Критерии приёмки

- [ ] Duplicate API тест проверяет статус дня, конечный день, часы заезда и выезда и ссылки разных пунктов; не только отдельные поля.
- [ ] Сокращение тура, где только конечный день ночного пункта исчезает, требует подтверждения, а отмена/ошибка сохраняет исходную запись.
- [ ] DayForm тест проверяет пустой/предложенный/свой статус и ограничение длины через onSave.
- [ ] ItemForm тест проверяет, что часы нового отеля передаются через onSubmit; неверный URL не открывается и не проходит onSubmit.
- [ ] Backend и frontend unit, lint, typecheck проходят без изменения продуктовой логики.
