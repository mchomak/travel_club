# Границы, решённые в спецификации

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| API поездок | Проверка и сохранение TripInput, восстановление/дублирование, контроль дат | Существующие CRUD, calculate и preview контракты с расширенными необязательными полями дня/пункта | Транзакции, связи по одному туру, подтверждение удаления |
| Расписание календаря | Преобразование дней и пунктов в видимые отрезки, полосы и маркеры | `buildCalendarEntries(days, items, visibleDates)` с позициями и типами записей | Деление через полночь, обрезку, разбор местных часов, размещение пересечений |
| Редактор поездки | Выбор даты, статус дня, открытие/сохранение пунктов, responsive-компоновка | Существующий TripInput/действия редактора и callback открытия пункта по id | Черновик, модальное/боковое представление, визуальное состояние |
| Расчёт стоимости | Прежняя финансовая модель | Существующие `calculate_trip(TripInput)` и клиентский предварительный расчёт | Decimal-формулы и распределение ночей |

Проверочные швы: API `TripInput` через существующие маршруты и чистая функция `buildCalendarEntries`; расчёт проверяется существующими публичными функциями. Визуальные действия проверяются через закрытую страницу редактора.

## Правила проекта для исполнителей

- Стек: FastAPI, SQLAlchemy 2, Alembic, PostgreSQL; Next, React, TypeScript, Tailwind; Docker Compose. Не добавлять новые зависимости без необходимости.
- Серверный расчёт `backend/app/pricing.py` — финансовый источник истины; сохранять существующие формулы и Decimal. Клиентский расчёт — предварительный.
- Сохранять whole-document TripInput, контроль версии, авторизацию, strict client preview и подтверждение сокращения заполненных дней. Новые поля аддитивные, миграция обязательна.
- Пункты без времени и общие расходы доступны вне сетки. Местные времена вылета/прибытия отображаются без пересчёта часовых поясов.
- Рабочие команды: `docker compose exec -T backend pytest -q`; `docker compose exec -T backend ruff check .`; `cd frontend; npm.cmd test; npm.cmd run lint; npm.cmd run typecheck; npm.cmd run build`; браузерный `npm.cmd run test:e2e` при запущенном Compose. Тестировать значимое поведение.
- Исполнитель не устанавливает отсутствующую зависимость самовольно: вернуть `BLOCKED` с точным препятствием. Не коммитить чужие незавершённые файлы. Передать список файлов, проверок и результата.

## Из таска 01 — сохранение расписания

- `DayInput.status: str` — необязательный по содержанию статус дня; старые записи читаются с пустой строкой.
- `ItemInput.end_day_id: UUID | None`, `check_in_time: time | None`, `check_out_time: time | None`, `external_url: str | None` — те же необязательные поля в TypeScript `ItemInput`.
- `tripInput()` передаёт новые поля API, `newItem()` создаёт безопасные значения; API сохраняет и возвращает поля при create/update/duplicate.
- Конечный день принадлежит тому же туру; URL — абсолютный http/https; дата/время окончания валидируется. Удаление задействованного конечного дня требует подтверждения.
- Миграция `8b97c412e6af_schedule_fields.py`; backend `pytest -q` — 48 passed, TypeScript typecheck зелёный на момент сдачи.

## Из таска 02 — календарная модель

- `buildCalendarEntries(days: DayInput[], items: ItemInput[], visibleDates: string[]): CalendarEntries` возвращает `events`, `hotelBars`, `markers` с геометрией видимых дат и пересечений.
- `TripCalendar({ days, items, onOpenItem, onSelectDate?, selectedDayId? })` выбирает неделю/три дня/один день по ширине и предоставляет переключение дат, кликабельные события и отели.
- CSS-классы `trip-calendar*` оставлены для таска 04; компонент и модель проверены unit-тестами.

## Из таска 03 — формы

- `ItemForm({ initial, trip, onSubmit, onCancel, onDirtyChange })` редактирует конечный день, часы отеля и URL.
- `DayForm({ day, onSave, onCancel, onDirtyChange })` редактирует статус дня.
- `Modal({ ..., variant?: "dialog" | "panel" })` задаёт класс `modal-panel`; CSS и подключение варианта к редактору принадлежат таску 04.

## Из таска 04 — конструктор

- `TripEditor` подключает `TripCalendar`, передаёт `onOpenItem`, `onSelectDate`, `selectedDayId`; `Modal variant="panel"` показывает `ItemForm`.
- Главный экран: краткая шапка, календарь, кнопки добавления, доступ к дню и untimed/general списку, финансовая сводка ниже. Адаптация 7/3/1 колонка в календаре.
