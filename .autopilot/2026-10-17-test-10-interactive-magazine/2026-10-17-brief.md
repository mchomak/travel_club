\# TRAVEL CLUB — TEST_10\
\## Interactive Editorial Magazine / Homepage Prototype\
\
\### 1. Цель задачи\
\
Создай новую экспериментальную страницу \`/test_10\`, используя существующую \`/test_8\` как техническую и визуальную основу.\
\
Мы хотим проверить принципиально новую концепцию главной Travel Club:\
\
\*\*Весь homepage существует как интерактивный журнал, а не как обычный сайт с вертикальной прокруткой.\*\*\
\
При открытии сайта пользователь видит знакомую вступительную анимацию Living Issue из \`/test_8\`.\
\
Журнал открывается, автоматически перелистывает несколько страниц и останавливается на первом рабочем развороте.\
\
После этого пользователь НЕ приближается к одной странице, как в старой концепции.\
\
Вместо этого он остаётся перед раскрытым журналом и перелистывает тематические развороты.\
\
Каждый разворот состоит из двух страниц с собственной композицией, фотографиями, типографикой и содержанием.\
\
\*\*Для первой итерации создай только три разворота:\*\*\
\
1\. HERO + FORMATS\
2\. NEXT ISSUE\
3\. THAILAND ’26\
\
Это полноценный UX/UI-эксперимент, а не готовая production-версия.\
\
Не изменяй существующие маршруты проекта.\

\# 4. Основная UX-механика\
\
\## 4.1. Начальная анимация\
\
Используй существующую анимацию Living Issue из \`/test_8\`.\
\
Нужно сохранить её характер:\
\
\- Физический объект журнала.\
\- Открытие обложки.\
\- Автоматическое перелистывание.\
\- Изгиб страниц, если он уже реализован.\
\- Свет и тени.\
\- Работу камеры.\
\- Общую кинематографическую подачу.\
\
Не переписывай качественную работающую 3D-анимацию с нуля.\
\
\### Что меняется\
\
В существующей концепции после вступительной анимации камера приближается к одной странице, которая превращается в homepage.\
\
В \`/test_10\` это больше не нужно.\
\
Новая последовательность:\
\
1\. Пользователь открывает \`/test_10\`.\
2\. На фоне Cloud появляется журнал.\
3\. Журнал открывается.\
4\. Автоматически перелистывает несколько страниц.\
5\. Камера устанавливается перед раскрытым журналом.\
6\. На экране появляется первый рабочий разворот HERO + FORMATS.\
7\. Журнал остаётся в этом положении.\
8\. Пользователь получает управление перелистыванием.\
\
\*\*Журнал не должен исчезать, превращаться в обычную страницу сайта или приближаться только к одной половине разворота.\*\*\
\
\### Требования к переходу\
\
Финальная позиция 3D-журнала должна визуально совпадать с положением интерактивного DOM-журнала.\
\
Не делай заметного скачка между анимацией и основным интерфейсом.\
\
Если для дальнейшего взаимодействия используется DOM/CSS, обеспечь максимально незаметную передачу изображения от 3D-сцены к DOM.\
\
Сохраняй геометрическую и визуальную непрерывность.\
\
Предусмотри кнопку пропуска вступительной анимации.\
\
После её завершения вступление не должно повторяться при каждом перелистывании.\

\# 5. Геометрия журнала\
\
Сосредоточься исключительно на desktop.\
\
Поддерживаемые ширины для первой итерации:\
\
\- 1280 px;\
\- 1440 px;\
\- 1728 px;\
\- 1920 px.\
\
Рекомендуемая базовая композиция:\
\
\- Cloud background на всю область браузера.\
\- Раскрытый журнал по центру.\
\- Две видимые страницы.\
\- Аккуратная центральная линия сгиба.\
\- Лёгкие тени под журналом.\
\- Небольшой физический объём страниц.\
\- Достаточные поля между журналом и краями viewport.\
\
У существующего сайта основная ширина контента приблизительно 980 px.\
\
Используй это как ориентир, но не как жёсткое ограничение для экспериментального журнала.\
\
Возможна более широкая композиция, например 1100–1250 px, если она значительно улучшает читаемость двух страниц.\
\
Проверь визуально разные размеры.\
\
\*\*Каждая половина журнала должна оставаться полноценной читаемой страницей.\*\*\
\
Не допускай:\
\
\- слишком мелкого текста;\
\- сжатых до нечитаемости таблиц;\
\- чрезмерно узких текстовых колонок;\
\- слишком большого пустого пространства;\
\- неправильных пропорций фотографий.\
\
Предпочтительная высота раскрытого журнала — такая, чтобы он помещался на стандартном desktop-экране без вертикальной прокрутки.\
\
Если экран недостаточно высокий, адаптируй масштаб и композицию, но не уменьшай содержимое до нечитаемого состояния.\
\
Подбери компромисс между реалистичными пропорциями печатного журнала и удобством веб-интерфейса.\

\# 6. Перелистывание разворотов\
\
После вступительной анимации начинается обычная навигация по журналу.\
\
\## Продолжительность\
\
\*\*300–600 мс на переход между разворотами.\*\*\
\
Желательный ориентир — 450 мс.\
\
Не используй тяжёлую физическую симуляцию бумаги между обычными разворотами.\
\
Возможные технологии:\
\
\- CSS transforms;\
\- CSS perspective;\
\- clip-path;\
\- лёгкие JavaScript-анимации;\
\- существующие animation utilities проекта.\
\
WebGL оставь преимущественно для начальной Living Issue.\
\
\### Требования к переходу\
\
Анимация должна визуально напоминать перелистывание страниц.\
\
При этом не нужен полноценный физический page curl.\
\
Достаточно убедительного движения листа, небольшой перспективы и аккуратной тени.\
\
Не заменяй перелистывание обычным fade-out / fade-in.\
\
Не должно возникать ощущения, будто сайт просто переключает слайды презентации.\
\
Приоритеты:\
\
1\. Плавность.\
2\. Быстрота.\
3\. Читаемость.\
4\. Визуальная непрерывность.\
5\. Минимальная нагрузка.\

\# 7. Управление журналом\
\
Реализуй несколько способов навигации.\
\
\### Мышь\
\
\- Клик по правому краю разворота — следующий.\
\- Клик по левому краю — предыдущий.\
\- Можно дополнительно использовать колесо мыши для переходов.\
\
Если используешь wheel navigation, ограничь её до одного перехода на осмысленный жест. Не допускай случайного перелистывания сразу нескольких разворотов.\
\
\### Клавиатура\
\
\- ArrowRight — следующий разворот.\
\- ArrowLeft — предыдущий разворот.\
\- Escape — закрытие дополнительных панелей, если они предусмотрены.\
\
\### UI\
\
Добавь компактную навигацию, которая органично вписывается в журнальный интерфейс.\
\
Например:\
\
\`← PREVIOUS    01 / 03    NEXT →\`\
\
Можно использовать:\
\
\- номера разворотов;\
\- тонкую progress-line;\
\- названия разделов;\
\- небольшие стрелки.\
\
Навигация не должна перекрывать важный контент.\
\
Также предусмотрите прямое переключение к нужному развороту через компактное оглавление или навигацию.\
\
Поддержи прямые ссылки, например:\
\
\`/test_10?spread=1\`\
\
\`/test_10?spread=2\`\
\
\`/test_10?spread=3\`\
\
При прямом переходе можно пропускать вступительную анимацию и сразу открывать соответствующий разворот.\
\
Браузерные Back / Forward должны корректно работать с историей переходов.\
\
На всех интерактивных элементах должны сохраняться focus states.\
\
Учитывай \`prefers-reduced-motion\`.\

\## ЛЕВАЯ СТРАНИЦА — HERO\
\
Содержание:\
\
\- Актуальный фирменный логотип Travel Club.\
\- Слоган «Куда — важно. С кем — важнее».\
\- Короткое объяснение проекта.\
\- Сильная пейзажная или документальная фотография.\
\- CTA «Обсудить поездку».\
\
Ориентир для описания, если аналогичный текст уже есть на \`/test_8\`:\

\### Композиция\
\
На левой странице должен доминировать фирменный логотип.\
\
Используй актуальные логотипы из проекта.\
\
Логотип может занимать верхнюю левую или центральную часть.\
\
Фотография должна быть достаточно крупной, чтобы создавать первое эмоциональное впечатление.\
\
Экспериментируй с композицией:\
\
\- Логотип над пейзажем.\
\- Логотип поверх фотографии.\
\- Фотография как нижняя половина страницы.\
\- Логотип и текст на Cloud с отдельным фото.\
\
Выбери наиболее удачный вариант по результатам визуального тестирования.\
\
Не превращай Hero в обычный рекламный баннер.\
\
\### CTA\

Основная кнопка:\
\
«Обсудить поездку ↗»\
\
Используй существующий маршрут заявки, если он есть.\
\
Не делай неработающую декоративную кнопку.\

\# 14. Desktop-only scope\

На этом этапе НЕ нужно делать полноценную мобильную версию.\

\- мобильное перелистывание;\
\- portrait-layout;\
\- ориентацию телефона;\
\- отдельный mobile UX;\

Это допустимо только для экспериментального \`/test_10\`.\

\- Нет выдуманных фактов.\

\
\- Перелистывание работает в обе стороны.\
\- Анимация укладывается в 300–600 мс.\
\- Нельзя случайно запустить одновременно несколько переходов.\

\- Клавиатура работает.\
\- Прямые ссылки работают.\
\- Навигация визуально не мешает журналу.\

Проверь desktop ширины:\
\
1280, 1440, 1728, 1920 px.\

Проверь как минимум две высоты viewport, включая 768 и 900 px.\
