## Что должно заработать

В интерфейсе открытого интервью исследователь видит расширенные модули, подходящие категории этого интервью, и может отфильтровать ими банк. После выбора можно добавить отдельные вопросы обычным способом. Полный банк и существующий поиск остаются доступными. После проверки сайт работает локально на ПК с обновлённым backend и frontend.

> «перезапусти сайт локально на этом ПК с обновленным списком вопросов»

## Разделы спецификации

Истории R03–R04; «Категории и маршрутизация модулей»; «Состояния и ошибки»; «Решения по реализации». API: интерфейс, описанный в .autopilot/2026-10-26-research-interview-questions--wip/interfaces.md.

## Критерии приёмки

- [ ] Типы клиента отражают expanded_modules backend-контракта. В picker доступны только модули текущего scenario_code; их фильтр показывает только входящие в модуль ещё не добавленные N-коды. «Весь банк» сохраняет поиск и добавление вопросов из общего списка.
- [ ] Для каждой категории проверены видимые модульные опции и фильтрация по таблице из спеки. N-группа отображается как «Расширенный банк CustDev». Существующий бренд-модуль и отключённый offers остаются с прежним поведением.
- [ ] Состояния без модулей и недоступной конфигурации понятны и не изображают успешную загрузку. Повторно добавленный код не дублируется; существующее содержимое ответов и исторические snapshots сохраняются.
- [ ] Компонентные и интеграционные проверки подтверждают выбор модулей для четырёх категорий. Playwright сценарий Research проверяет доступность модулей для маршрутов либо эквивалентное автоматизированное покрытие каждого из четырёх picker-вариантов.
- [ ] Выполнить frontend lint, typecheck, тесты и production build; из корня выполнить docker compose up -d --build --wait и проверить healthy backend/frontend и ответ страницы localhost:3000 (200). Research API защищён авторизацией: без сессии 401 ожидаем. Проверить authenticated GET /api/research/config тестом tests/test_research_api.py::test_authenticated_configuration_endpoint_exposes_editable_questionnaire (140 вопросов, 28 гипотез, 10 модулей) и контейнерным валидатором; PostgreSQL volume сохранить.

## Границы

Следовать source-grounded матрице применимости из спеки; не добавлять новые категории или scoring. Оставить основной список интервью и механизм сохранения снимка прежними. Не менять schema PostgreSQL.
