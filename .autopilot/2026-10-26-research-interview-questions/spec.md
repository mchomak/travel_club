# Спецификация: TC Research 2.2

## Задача

Обновить закрытый TC Research банк вопросов по документу TC — Research — Audience, JTBD & CustDev — v2.2 Expanded Interviews.docx и сделать расширенные тематические модули доступными для подходящей категории респондента. Сейчас серверный банк содержит 82 базовых вопроса. Их тексты и коды уже полностью совпадают с документом. Версия 2.2 добавляет 58 вопросов, которые сайт пока не показывает.

## Решение

Сохранить текущую модель: backend хранит JSON-банк, screening, правила классификации и сценарии; API отдаёт конфигурацию; интервью сохраняет снимок набора вопросов. Новые вопросы и гипотезы добавляются в банк как данные. Десять расширенных модулей получают явные связи с действующими сценариями, а форма добавления вопросов предлагает фильтр по модулю для категории текущего интервью. Интервьюер добавляет модуль по цели беседы; вопросы из всех модулей не вставляются автоматически в каждое интервью.

## Категории и маршрутизация модулей

Категории респондентов не заменяются исследовательскими модулями.

Основные маршруты 82 базовых вопросов, сверенные с DOCX:

| Категория | Screening | Основные вопросы |
|---|---|---|
| Trips / опытный путешественник | S01–S05 | G01, G02, G05, G06, G07, G10, T01, T03, T04, T07, T10, T14 |
| Trips / начинающий путешественник | S01–S05 | G01, G04, G05, G06, G10, G12, T02, T05, T06, T08, T14, T15 |
| Travel Design | S01–S06 | G01, G04, G07, G08, G10, D01, D02, D04, D05, D07, D08 |
| Travel Ready | S01–S06 | G01, G04, G07, G10, R01, R02, R03, R05, R06, R12 |
| Экосистема / бренд, необязательно | — | G01, G05, G09, G10, B01, B02, B03, B05, B07, B08 |

Для каждого маршрута сравнить коды и тексты со всем DOCX 2.2; в текущем банке все 82 базовых вопроса уже совпадают. Новые N-вопросы остаются в расширенных модулях и доступны из picker согласно матрице ниже. Именно маршрут и категория респондента, а не только наличие вопроса в общем банке, проверяются в сценарном тесте.

 Действующая автоматическая классификация и screening остаются неизменными: новые вопросы 09A не являются screening-вопросами и не вводят критериев для scoring.

DOCX задаёт четыре верхнеуровневых маршрута (Trips, Design, Ready, экосистема), назначение базовых разделов и цели/связи новых модулей, но не содержит готовой полной матрицы «категория × модуль». Поэтому указанное распределение — ASSUMPTION, выводимый из этого контекста. До реализации сверить каждую строку и ячейку с назначением раздела и модуля, формулировкой проверяемой гипотезы и указанными в DOCX связями с прежними вопросами; сохранить только обоснованные тематические связи. Это правило и итоговая таблица должны быть проверяемыми тестами для всех четырёх категорий. Модуль без обоснованной связи с категорией остаётся в общем банке, но не появляется в её тематическом фильтре. Эта матрица не меняет screening или scoring. Общий банк остаётся доступен для поиска вручную. В picker сначала показываются модули, релевантные категории текущего интервью; интервьюер может переключиться на весь банк. По документу рекомендовано выбирать один тематический модуль, а не задавать весь банк одному респонденту.

## Состояния и ошибки

- Новый респондент проходит действующий screening и получает один из четырёх текущих сценариев. Никакие новые поля не обязательны для создания интервью.
- Модуль становится доступен в существующей области «Добавить вопрос» после загрузки конфигурации; выбранный модуль фильтрует код и текст вопросов. Общий поиск и добавление отдельных вопросов остаются доступны.
- Если у категории нет подходящего тематического модуля, picker сообщает об этом и оставляет переключение на весь банк.
- Если конфигурация не загрузилась или backend сообщает ошибки валидации, не показывать пустой список как успешный результат: сохранить существующее состояние ошибки/недоступности picker.
- Повторное добавление кода, уже входящего в снимок, не создаёт дубликат. Ошибка сохранения не удаляет уже введённые ответы.
- Закрытие или обновление страницы не меняет уже сохранённый снимок вопросов; добавление использует существующий endpoint, сохраняющий обновлённый снимок.

## Решения по реализации

- Источник истины — переданный DOCX v2.2. Не редактировать формулировки 82 совпавших базовых вопросов.
- Для нового вопроса хранить исходный ID и текст, код модуля, уточнение, код(ы) гипотезы и доступные поля существующего контракта вопроса. Не придумывать новые факты о респондентах или правила исследования.
- В scenarios.json хранить каталог модулей v2.2 в форме: code, label, question_codes, hypothesis_ids, scenario_codes. Серверный валидатор проверяет наличие/уникальность всех ID и ссылки модуля на существующие вопросы, гипотезы и категории.
- В интерфейсе TC Research добавить выбор модуля в существующую область «Добавить вопрос». По выбранному интервью показываются только модули из его категории; фильтр «Весь банк» сохраняет доступ к остальным вопросам. Поиск и добавление существующего вопроса работают как раньше.
- Расширить название группы N в списке интервью до «Расширенный банк CustDev».
- Не менять таблицы PostgreSQL и не добавлять миграцию. Созданный ранее question_snapshot сохраняет содержимое; новые интервью получают обновлённый каталог, а новое добавление в незавершённое интервью записывает выбранный вопрос в его снимок.
- Сохранить текущие защитные ограничения: модуль X предложений не включать. Новые N-вопросы с ценами остаются отдельными открытыми вопросами из DOCX и не включают X автоматически.
- После реализации выполнить нужные проверки и пересобрать/перезапустить локальные Compose backend и frontend; PostgreSQL volume не удалять.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R02 — новые категории, поля screening или автоматические правила scoring | В документе v2.2 для них нет определений; менять классификацию по тематическим модулям было бы неподтверждённым бизнес-решением |
| R03 — автоматическая вставка всех новых вопросов в основное интервью | В DOCX сказано выбирать один тематический модуль и не задавать весь банк всем респондентам |
| R04 — изменение ответов в уже завершённых снимках интервью | Исторические снимки сохраняют фактически заданный набор вопросов; замена задним числом исказила бы историю |
| Real-world offer tests X01–X12 | Модуль офферов в конфигурации выключен до готовности реальных условий; эта задача его не включает |
