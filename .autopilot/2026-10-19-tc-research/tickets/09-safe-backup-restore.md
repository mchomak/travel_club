# Ticket 09 — Безопасное восстановление PostgreSQL из backup

## Требование

R67 — Дать инструкции для запуска/VPS/JSON/backups.

## Найденный дефект

Восстановление в docs/tc-research/backup.md продолжает команды после ошибки создания целевой базы. При существующей базе pg_restore --clean способен перезаписать её объекты, а последующая проверка может выглядеть успешной несмотря на ошибку восстановления.

## Сделать

Обновить только runbook восстановления так, чтобы команды останавливались при любой ошибке, целевая БД явно задавалась как новая/пустая и уже существующая база отклонялась до pg_restore. Добавить fail-fast параметры pg_restore/psql, где уместно. Не давать команду автоматического удаления базы/тома и не использовать имена или значения из окружения пользователя.

## Проверка

- Команды безопасны для PowerShell/Windows и VPS shell либо ясно разделены по платформам.
- Повторное восстановление не перезаписывает существующую БД молча.
- Ошибка restore не приводит к сообщению об успешной проверке.
- Ссылки/пути в документе существуют.
- git diff --check проходит.
- Изменён только docs/tc-research/backup.md.
