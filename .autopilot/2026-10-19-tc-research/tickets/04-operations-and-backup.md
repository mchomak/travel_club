# 04 — Запуск, домен и резервные копии

**Требования:** R06–R07, R61, R63, R67<br>
**Зависит от:** 02, 03<br>
**Зона:** `docs/tc-research/`, `deploy/nginx/`, `deploy/tests/test_nginx_render.py`<br>
**Волна:** 4<br>
**Статус:** pending

## Что должно работать

Владелец проекта может поднять Research локально, задать отдельный HTTPS поддомен через конфигурацию, развернуть тот же сервис на VPS, проверить/обновить JSON и сделать настоящую резервную копию/восстановление PostgreSQL.

## Из брифа, дословно

> «Поддомен должен настраиваться через конфигурацию, например `research.<наш-домен>`. Не зашивай конкретный домен в код»
> «Всё должно работать через HTTPS»
> «Подготовь также простую инструкцию для создания и восстановления резервной копии БД через `pg_dump`/`pg_restore`»

## Разделы спецификации

`spec.md` §§5, 9, 11. Не менять DNS, сертификаты и удалённый VPS в этой задаче.

## Критерии приёмки

- [ ] Инструкция показывает, как задать `RESEARCH_ORIGIN` без домена, зашитого в код или репозиторий; неизвестный домен не выдуман.
- [ ] Краткая инструкция запуска перечисляет фактические Windows/Powershell команды проекта и `/research`; migration/bootstrap работают тем же способом, что Travel Club.
- [ ] Nginx renderer принимает валидированный `--server-name` для hostname, сохраняет backward compatibility с текущим IP usage, безопасно формирует Host/redirect/server_name; тесты запрещают инъекции и покрывают домен и IPv4.
- [ ] Инструкция для VPS описывает DNS, отдельный reverse proxy HTTPS, frontend upstream, проксирование API и Origin, повторное использование защищённой admin-сессии и сертификат домена; прямо указывает, что реальный VPS не настроен.
- [ ] JSON runbook перечисляет конкретные файлы банка/сценариев/rules, проверку командой, версионирование snapshot и безопасный rebuild/restart.
- [ ] Backup runbook содержит команды `pg_dump -Fc` и `pg_restore --clean --if-exists` для Compose и проверки восстановления на отдельной БД; подчёркивает, что XLSX не backup.
- [ ] `.env.example` перечисляет пустой `RESEARCH_ORIGIN`; deploy Compose передаёт значение backend, если оно задано.
- [ ] Команды конфигурации/Compose и ссылки проверены по репозиторию; не внесены секреты или фиктивные DNS-значения.

## Работа по TDD/проверке

Для конфигурации сначала тесты принятия `RESEARCH_ORIGIN` и существующего `ALLOWED_ORIGIN` отдельно. Документационные команды проверить синтаксисом Compose/shell и сверить с фактическими именами env и сервисов.
