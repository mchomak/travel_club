# Ticket 10 — Просмотр истории по snapshot при проблеме с текущей конфигурацией

## Требования

R53 — карточка показывает вопросы сценария и сохранённые ответы.
R57 — старое интервью сохраняет исходные формулировки из snapshot, даже если актуальный JSON позднее изменился или стал невалидным.

## Найденный дефект

Карточка респондента требует успешной загрузки текущей конфигурации и без проверки обращается к `config.scenarios.scenarios`. Ошибка загрузки или некорректная структура current config блокирует просмотр интервью, хотя запись уже содержит полный `question_snapshot`.

## Сделать

Исправить загрузку и отображение в `frontend/src/components/research/respondent-detail.tsx`, чтобы существующая карточка и интервью могли открываться по данным респондента и сохранённому snapshot без зависимости от доступности/валидности текущего вопросника. Показывать точные сохранённые коды, тексты, подсказки и ответы, включая пустые ответы, если API detail успешно вернул snapshot. Текущую конфигурацию использовать только для операций, которым она нужна, например добавления новых вопросов; если она недоступна, блокировать только эти операции и показывать понятное сообщение. При отсутствии screening labels безопасно отобразить сохранённые значения по ключам, не ломая остальные разделы.

Добавить покрывающие тесты для ошибки загрузки config и успешно загруженного, но структурно неполного config. Проверить, что saved snapshot и ответы остаются видимыми и нет необработанного исключения. Не менять backend API, сохранённые данные, публичные страницы, классификацию или модель снимка.

## Проверка

- Тест detail показывает snapshot и ответы, когда config endpoint отклонён.
- Тест detail показывает snapshot и ответы, когда config получен без `scenarios`.
- Операции, требующие актуального config, остаются закрытыми с понятным сообщением.
- Существующие тесты компонента проходят.
- `npm.cmd run typecheck` и `git diff --check` проходят.
- Изменения ограничены detail компонентом и его тестом.
