# TC Research — итог приёмки (20 октября 2026)

## Решения, принятые за вас

- Для двух основателей переиспользована существующая защищённая admin-сессия Travel Club: она закрывает экран Research, API и экспорт. Отдельные аккаунты и роли не добавлены.
- Баллы и пороги классификации оставлены редактируемыми стартовыми значениями, а не представлены как подтверждённая типология клиентов.
- DOCX взят за первичный источник порядка сценариев. В сравнении с массивами из задания начинающий маршрут добавляет G10/G12, Travel Design — G08/G10, Travel Ready — G10; различия описаны в `docs/tc-research/json-data.md`. B подключается по выбору в конец интервью, X остаётся выключенным до появления реальных условий и цен.
- Для ответов длиннее лимита ячейки Excel экспорт делит текст на дополнительные колонки `Answer Text (part N)` в той же строке, чтобы не терять символы и сохранять одну строку на вопрос; решение записано в ADR 0027.

## Готово

TC Research встроен в существующий Travel Club: `/research`, `/research/new`, `/research/[id]`. Создание респондента сохраняет анкету в PostgreSQL до старта интервью; правила категории объяснимы, интервьюер может выбрать другой сценарий. Экран интервью использует сохранённый снимок формулировок, автосохранение с подтверждением сервера, локальный черновик при сбое и защиту от устаревшей записи. Завершённые интервью остаются доступны для редактирования.

Список поддерживает поиск, фильтры, сортировку и карточку. XLSX содержит пять листов; фильтр списка не ограничивает выгрузку. Скрининг, банк вопросов, гипотезы, классификация и сценарии редактируются в JSON. Есть инструкции для локального запуска, VPS/HTTPS, обновления JSON и резервного копирования PostgreSQL.

**Локальный запуск** из корня репозитория:

```powershell
python scripts/init_env.py
docker compose up -d --build --wait
docker compose exec backend python -m app.bootstrap
```

После интерактивного создания первого администратора открой `http://localhost:3000/research` и войди существующей admin-учётной записью. Для HTTPS-поддомена см. `docs/tc-research/deployment.md`.

## Что нужно от тебя

Чтобы открыть Research на реальном поддомене, нужны точное имя домена `research.<ваш-домен>`, публичный IP/VPS и доступ к его конфигурации, управление DNS и выбранный HTTPS-порт. Также потребуется контактный email для выпуска сертификата. В коде и Git домен или секреты не зашиты; значения задаются в серверном окружении. Пока этого нет, приложение проверено локально, но не опубликовано.

Для первого локального запуска создай admin-учётную запись через команду bootstrap выше. Резервная копия PostgreSQL и восстановление в отдельную базу описаны в `docs/tc-research/backup.md`.

## Что не вошло

Требований, помеченных как удалённые или отложенные, нет. Реальное VPS-развёртывание и независимая оценка визуальной полировки остались частично проверенными пунктами R06/R62/R63, как отмечено выше.

## Что пошло не по плану

Манифест не содержит D##-отклонений. После ревью были добавлены и закрыты исправления по безопасной активации Nginx vhost, полноте S02/S03, сверке маршрутов с DOCX, textarea для JSON-анкеты, сохранению длинных XLSX-ответов и поведению при некорректной конфигурации сценария.

Оставлены две неблокирующие заметки из ревью: при ошибке до проверки файла резервной копии тестовая пустая БД может быть создана, но существующая база не перезаписывается; тестовый helper для подписи отдельных screening-полей продублирован и может потребовать синхронного обновления при будущих изменениях.

В одном из ранних проверочных прогонов очистка затронула 62 синтетических респондента, 62 интервью и 33 ответа в отдельной тестовой БД `tc_research_baseline`. Общая локальная и production БД Travel Club не затрагивались. Последняя независимая приёмка использовала другой отдельный volume `tc-research-blind_postgres_data`, который остановлен и сохранён.

## Открытые вопросы

- Реальный домен, DNS, VPS и HTTPS ещё не настроены — после предоставления значений можно выполнить публикацию и проверить сертификат снаружи.
- Визуальная полировка не получила отдельной независимой оценки; базовая адаптивность проверена на 320 и 390 px.
- Backend suite (149 тестов) и Ruff прошли на изолированной БД после последнего backend-изменения; повторный финальный прогон в этой итерации не выполнялся.
