# TC Research — спецификация

## 1. Цель и границы

Внутренний инструмент CustDev для двух основателей Travel Club: сохранять screening до начала беседы, рекомендовать сценарий, вести интервью с подтверждённым сервером автосохранением, возвращаться к карточке и экспортировать исследовательскую базу. Респондент не входит и не заполняет форму самостоятельно.

Отдельная зона `/research` и API `/api/research` используют текущие Next.js, FastAPI, SQLAlchemy 2, Alembic и PostgreSQL. Таблицы с префиксом `research_`; они не связаны с поездками/CRM. Публичные маршруты и оформление сайта не меняются. Нет регистрации, новых ролей, AI, оплаты, почты, Telegram, аудиофайлов, CRM, сложных дашбордов и тяжёлых UI зависимостей.

## 2. Пользовательский поток

1. `/research` показывает пустое состояние с «Новый респондент», список, поиск, фильтры, сортировку, счётчики и «Экспорт в Excel».
2. `/research/new` показывает девять требуемых профильных полей: имя/псевдоним, возраст/диапазон, город, самостоятельные зарубежные поездки за 24 месяца, опыт групповых поездок, планы, платные услуги, обычный способ организации, трудность подготовки. Опциональный исходный S04 «роль в выборе и оплате» доступен в свёрнутом дополнительном блоке. Подписи, порядок, типы полей и варианты загружаются из JSON, а не задаются во frontend; закрытые поля поддерживают «Другое» и/или «Затрудняюсь ответить» там, где это подходит. Имя и город — свободный текст. Ответы необязательны. POST создаёт респондента и draft-интервью одной транзакцией, поэтому запись существует до начала беседы.
3. Сервер вычисляет четыре прозрачных балла из JSON-конфигурации, возвращает предложенную и альтернативную категории, объяснение и силу сигнала. Интервьюер может выбрать любую категорию. Перед переходом видна карточка с именем и возрастом, городом, опытом самостоятельных поездок и групповых поездок, сценарием и краткими причинами рекомендации. «Перейти к интервью» сохраняет final category/override, запускает интервью и показывает вопросы.
4. `/research/[id]` показывает компактную закреплённую шапку с именем, возрастом/диапазоном, городом, опытом самостоятельных поездок, опытом групповых поездок, финальной категорией, сценарием и статусом draft/in_progress/completed; полная анкета свёрнута. Ниже вопросы сценария в установленном порядке и прогресс по непустым ответам. Оглавление ведёт к каждому вопросу. Вопрос — блок с кодом и большим textarea; подсказка раскрывается по запросу. Интервьюер может добавить вопросы любого раздела; B по выбору добавляется в конец. X скрыт и недоступен, пока `offers_enabled=false`.
5. Каждый ответ сохраняется с debounce и blur. «Сохранено» появляется только после успешного API ответа. До этого текст остаётся в React и локальном черновике по паре `interview_id/question_code`; при `online` он отправляется повторно. Dirty форма предупреждает перед уходом. Revision/CAS не даёт старой записи перезаписать новую: равный повтор идемпотентен, устаревшая запись получает 409 и сохраняет локальный текст до разрешения конфликта.
6. «Завершить интервью» показывает: «Вы уверены, что хотите завершить интервью? Некоторые вопросы могут остаться без ответа. Все сохранённые данные останутся доступны для просмотра и редактирования». Кнопки «Отмена»/«Да, завершить». После подтверждения frontend дожидается всех сохранений; ошибка блокирует completion и объясняет несохранённое. Пустые ответы разрешены. Сервер ставит `completed_at` и `completed`; позднее редактирование обновляет `updated_at`, статус остаётся completed. После успешного завершения пользователь возвращается на карточку респондента, откуда доступен переход к списку.
7. Карточка содержит основные сведения, screening-ответы и полный snapshot вопросов с ответами. Пустой вопрос можно заполнить позднее. Обновление анкеты показывает новую рекомендацию и предлагает пересчёт; сценарий и ответы не меняются автоматически и не удаляются.

## 3. JSON и исходный DOCX

- `backend/app/research_data/questions.json`: ровно 82 исходных вопроса S/G/T/D/R/B/X и H01–H17. Ожидаемый inventory вопросов: S01–S06, G01–G12, T01–T16, D01–D12, R01–R12, B01–B12, X01–X12; гипотез: H01–H17. Вопрос хранит `code`, `section`, `text`, `type`, `options`, `follow_ups`, `hypothesis_ids`, `interpretation` и точное `answer_guidance` из источника. `bank_version` — DOCX редакции 1.0 от 16.10.2026.
- `scenarios.json`: независимая версия массива кодов для четырёх маршрутов, с B/X приложениями и флагом X выключен.
- `screening.json`: девять профильных полей, варианты и метаданные источника. Формулировки DOCX S01–S06 остаются неизменными; поля, которых нет в DOCX, помечены как заданные пользователем.
- `classification.json`: веса/порог четырёх категорий, tie-break и тексты объяснений. JSON изменяется без правки React.

На загрузке и в тесте проверяются точный inventory/уникальность кодов, разрешение всех сценарных кодов, ссылок на гипотезы и наличие описаний H01–H17. Команда `python -m app.research_bank validate` выводит все отсутствующие/повторные/неизвестные коды и их источники; конфигурационный API также сообщает missing codes. При неполном/невалидном банке создание и начало сценария блокируются с понятным списком проблем, а существующие snapshots продолжают открываться. Новый или исправленный банк — JSON в `research_data/`, затем та же команда проверяет его перед вводом в работу. Старые интервью хранят полный snapshot каждого вопроса, версию сценария и банка; редактирование JSON влияет только на новые записи.

DOCX — первичный источник маршрутов. S01–S05 входят в предварительную анкету у опытного/начинающего Trips; S01–S06 — у индивидуальных сценариев. После удаления S-кодов из массива непосредственно задаваемых вопросов основные порядки таковы: опытный — `G01,G02,G05,G06,G07,G10,T01,T03,T04,T07,T10,T14`; начинающий — `G01,G04,G05,G06,G10,G12,T02,T05,T06,T08,T14,T15`; Design — `G01,G04,G07,G08,G10,D01,D02,D04,D05,D07,D08`; Ready — `G01,G04,G07,G10,R01,R02,R03,R05,R06,R12`. В предоставленных пользователем массивах для начинающего отсутствуют G10/G12, для Design — G08/G10, для Ready — G10; эти расхождения разрешены в пользу DOCX. В DOCX также есть условные X06 у Design и X07/X08 у Ready; X остаётся вне базовых массивов и выключен до реальных цены и условий. Общий ecosystem маршрут DOCX `G01,G05,G09,G10,B01,B02,B03,B05,B07,B08` не создаёт пятую категорию: B доступен как ручное приложение в конце любого сценария.

## 4. Правила рекомендации

Чистая backend функция принимает нормализованные ответы и цель Trips/individual services. Возвращает `suggested_category`, вторую по score `alternative_category`, четыре score и список сработавших причин. Начальные настраиваемые допущения: 3+ самостоятельных поездки за 24 месяца усиливают experienced; 0–1 — beginner; опыт группы/текущие планы и цель Trips усиливают соответствующие Trip-сегменты; маршрутные/логистические трудности или оплата маршрута усиливают Design; трудность координации, услуги организации или цель individual services усиливают Ready. Побеждает наибольший score; равенства разрешаются JSON priority. Без сигналов использовать явно обозначенное слабое стартовое предложение beginner с альтернативой Design и объяснением «мало данных». Это рабочая рекомендация, не диагноз; интервьюер всегда принимает окончательное решение.

**ASSUMPTION:** стартовые баллы и пороги не заданы бизнесом; они редактируются в JSON и в интерфейсе объясняются фактами сработавших правил.

## 5. API и модули

Все исследовательские routes требуют текущий `Admin` session dependency; layout `/research` вызывает существующий Next `requireAdmin()`. API защищён сервером даже при прямом запросе. Новых ролей/паролей нет. HTTPS завершается на существующем Nginx; `RESEARCH_ORIGIN` добавляется к разрешённым origin и не заменяет `ALLOWED_ORIGIN`.

`backend/app/research.py` владеет HTTP/транзакциями; `research_domain.py` — классификацией, JSON validation, snapshot и XLSX. Модели добавляются в `models.py`, DTO — в `schemas.py`, router подключается из `main.py`. Независимый UI находится в `frontend/src/app/research/`, компоненты — `frontend/src/components/research/`, API/типы — `frontend/src/lib/research.ts`. Публичные страницы не импортируют research UI.

Endpoints: GET config/questions; GET respondents с `q/category/status/sort/page/page_size` и counts; POST respondent + draft interview; GET detail; PATCH screening с явным пересчётом recommendation; POST start/selection; POST append questions; PUT answer с `expected_revision`; POST complete; GET полный `.xlsx` без фильтров. Таблица списка содержит колонки «Имя», «Возраст», «Город», «Категория», «Статус», «Последнее изменение» и показывает общее количество, завершённые и незавершённые интервью. 404 не раскрывает внутренности; 409 возвращает свежую revision и безопасно сохраняет клиентский текст.

## 6. База данных

- `research_respondents`: UUID PK, name, age/age_range, city, screening_answers JSONB, research_goal, suggested/final category, override, recommendation JSONB и timestamps.
- `research_interviews`: UUID PK, FK respondent, scenario code/version, bank version, status check `draft/in_progress/completed`, full `question_snapshot` JSONB, started/completed/created/updated timestamps. Текущий сценарий создания порождает один draft; таблица сохраняет возможность нескольких интервью и не запрещает историю уникальным ограничением.
- `research_answers`: UUID PK, FK interview cascade, question code, `answer_text TEXT`, positive `revision`, updated_at, unique `(interview_id, question_code)`.

Индексы по respondent created/updated/category, интервью status/date, FK и unique answer pair. Миграция аддитивная. Создание, snapshot и completion транзакционные. Ответы пишутся CAS по revision; constraint защищает от гонки вставки. Screening/category updates не заменяют ответов.

## 7. Автосохранение и история

Состояние поля: `clean`, `dirty`, `saving`, `saved`, `offline`, `conflict`, `error`. Локальная запись помогает восстановлению, но не объявляется серверным сохранением. При открытии сначала загружается серверная версия, затем сравнивается локальный черновик по времени/revision: более свежий сохраняется в textarea и отправляется; после ack локальный draft удаляется. Ошибка не очищает текст. Конфликт явно показывает, что сервер уже содержит другую revision, и предлагает сохранить локальный текст с актуальной revision. Пустые поля и завершённые интервью можно дополнять.

## 8. Excel

Сервер собирает workbook через `openpyxl` и возвращает `tc-research-YYYY-MM-DD.xlsx`. Экспорт не принимает UI filters и включает всё. Листы: Respondents (1 строка на человека; screening в отдельных столбцах), Interviews, Answers (1 строка на каждый snapshot-вопрос включая пустой: IDs, имя/категория, code/text/answer/hypothesis IDs/updated_at), Questions (использованные формулировки и bank version), Hypotheses (H01–H17 и исходное описание). Длинный текст переносится, русский и новые строки сохраняются. Пользовательский текст принудительно задаётся как string cell, а не формула. При превышении лимита Excel 32,767 символов ответ продолжается в дополнительных `Answer Text (part N)` колонках той же строки; тест читает workbook обратно и собирает текст без потерь. Все листы одного consistency snapshot.

## 9. Конфигурация, деплой и backup

`.env.example` содержит пустой `RESEARCH_ORIGIN` без секретов и домена пользователя; deploy Compose передаёт это значение backend. Next rewrite продолжает проксировать `/api`; research URL относительный. Существующий Nginx renderer принимает проверенное `--server-name` (по умолчанию прежний runtime IP), чтобы можно было сформировать отдельный HTTPS virtual host для `research.<domain>` на том же frontend upstream; runbook описывает DNS, сертификат домена, forwarded Host/Origin и отдельную admin-сессию. Значения задаёт владелец VPS; DNS и сервер не меняются в этой работе. В README/runbook — локальный `/research`, миграции, обновление JSON с версионированием и перезапуск/rebuild frontend/backend.

Backup инструкция: `pg_dump -Fc` из PostgreSQL контейнера в файл за пределами репозитория; восстановление `pg_restore --clean --if-exists` в подготовленную БД; проверка наличия таблиц и данных. XLSX не заменяет backup.

## 10. Дизайн и проверка

Палитра: фон `#F5F7FB`, поверхности `#FFFFFF`, глубокий синий `#173F7A`, текст `#17253B`, вторичный `#5D6B80`, линии `#DCE3ED`, успех `#14795D`, ошибка `#A83232`. Системный sans с Inter/Segoe UI/Aptos fallback. На desktop — компактная навигация, основной интервью-текст и правая полоса контекста/прогресса; на mobile таблица становится карточками, полоса сворачивается, поле ответа остаётся широким. Номерные маркеры относятся только к последовательности вопросов. Keyboard focus, понятные labels, контраст и reduced motion. Не строить декоративный SaaS dashboard.

Backend tests: JSON bank (точные 82 вопроса/17 гипотез, ожидаемый inventory, uniqueness/references), category scores, auth, atomic create, screening recalc, old snapshots, CAS/идемпотентность, пустое completion, фактические Excel sheets/values/formula escaping/long answer. Frontend unit/e2e: create/override/scenario, hints, progress, debounce/blur, reload, offline queue/reconnect, dirty warning, completion and edit-after, screening recalc safety, search/filter/export. Отдельно проверяются все 18 приёмочных сценариев из §18: (1) создать респондента; (2) сохранить screening; (3) определить категорию; (4) вручную изменить; (5) показать правильный сценарий; (6) сохранить ответ; (7) обновить страницу; (8) сеть пропала/восстановилась; (9) предупреждение при уходе с dirty-полем; (10) завершение с пустыми полями; (11) второе подтверждение; (12) открыть completed; (13) дополнить completed; (14) изменить screening без потери ответов; (15) обновить JSON при сохранённом старом snapshot; (16) поиск и фильтры; (17) проверить фактические данные Excel; (18) повторить экспорт после изменения ответа.

## 11. Неизвестное и вне рамок

Фактический домен, DNS и сертификат не предоставлены; конфигурация и generic инструкция будут готовы, но реальный VPS deployment не считается выполненным. **ASSUMPTION:** используется существующая защищённая admin-сессия приложения вместо второй Basic Auth пары. **ASSUMPTION:** интерфейс показывает любое правило как предварительный сигнал; начальные баллы требуют будущей проверки исследовательской командой. Никаких выдуманных цен, доменов, вопросов или секретов.

Вне рамок: изменение DNS/TLS на VPS, регистрация/роли, внешняя авторизация, оплата, сообщения, аудиозаписи, AI, CRM, графики рынка.
