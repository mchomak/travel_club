\## 5. Общая система анимаций\
\
Разработай единую систему motion design из шести взаимосвязанных приёмов.\
\
1\. \*\*REVEAL\*\* — постепенное раскрытие заголовков слева направо.\
2\. \*\*CASCADE\*\* — последовательное появление текстовых блоков.\
3\. \*\*DRAW\*\* — прорисовка разделительных линий и подчёркиваний.\
4\. \*\*ICON MOTION\*\* — короткие анимации линейных иконок.\
5\. \*\*HOVER\*\* — микроинтеракции ссылок, CTA и строк продуктов.\
6\. \*\*NAVIGATION MOTION\*\* — плавная индикация активной главы в нижней навигации.\
\
Необязательно применять все эффекты к каждому элементу. Выбирай подходящие решения для конкретной композиции.\
\
Используй существующий стек проекта. Не добавляй новые библиотеки без реальной необходимости.\

\## 6. Эффект REVEAL — раскрытие заголовков\
\
Это главный новый эффект.\
\
При активации содержательного разворота заголовок постепенно открывается слева направо, словно проявляется на бумаге.\
\
Визуально это должно напоминать раскрытие напечатанного текста, а не набор символов на клавиатуре.\
\
Предпочтительно использовать маску, clipping или аналогичный механизм, сохраняющий исходную типографику. Выбери техническую реализацию самостоятельно с учётом архитектуры проекта.\
\
\### Где использовать\
\
\- «С нами в путь».\
\- «Люди, с которых начался Travel Club».\
\- Имена Василисы и Рамиля на развороте «О нас».\
\- «Следующая история — вместе».\
\- Заголовки THAILAND и CHINA, если эффект не конфликтует с фотографиями.\
\- ARCHIVE.\
\- «Не только куда».\
\- «Начнём с разговора».\
\
Для крупных графических надписей, взаимодействующих с изображениями, можно оставить исходное поведение, если маска ухудшает композицию.\
\
\### Рекомендуемые тайминги\
\
\- Одна строка: 350–550 мс.\
\- Многострочный заголовок: 450–700 мс на весь блок.\
\- Между строками допустима небольшая задержка.\
\
Не используй медленный посимвольный эффект. Пользователь должен практически сразу получить возможность читать заголовок.\

\## 7. Эффект CASCADE — последовательное появление текста\
\
После заголовка постепенно появляются связанные с ним элементы:\
\
1\. Подзаголовок или вводная фраза.\
2\. Основной текст.\
3\. Дополнительные смысловые блоки.\
4\. Ссылки и CTA.\
\
Используй комбинацию плавного изменения прозрачности и небольшого вертикального смещения. Движение должно быть едва заметным.\
\
Рекомендуемые параметры:\
\
\- Продолжительность обычного текстового блока: 250–400 мс.\
\- Смещение: примерно 6–12 px.\
\- Интервал между смысловыми группами: 60–120 мс.\
\- Общая продолжительность появления основных элементов разворота: примерно 0,8–1,4 секунды.\
\
Не анимируй каждое предложение отдельно. Объединяй элементы в логические группы.\

\## 8. Эффект DRAW — прорисовка линий\
\
Используй существующие тонкие линии как естественную часть анимации.\
\
Подходящие элементы:\
\
\- Разделители между строками продуктов.\
\- Горизонтальные линии под колонтитулами.\
\- Разделители смысловых блоков.\
\- Подчёркивания заголовков и ссылок.\
\- Линии, отделяющие основной текст от нижних подписей.\
\
Линии постепенно удлиняются слева направо. Для вертикальных линий допустима прорисовка сверху вниз.\
\
Рекомендуемые тайминги:\
\
\- Короткие линии: 200–300 мс.\
\- Длинные разделители: 300–450 мс.\
\- Подчёркивания ссылок при наведении: 150–250 мс.\
\
Сохрани исходные толщину и цвет линий. Не добавляй свечение, объёмные эффекты и лишнюю декоративность.\
\
Не запускай все линии одновременно. Синхронизируй их появление с соответствующими текстовыми блоками.\

\## 9. Линейные иконки\
\
Развивай существующую систему иконок, не создавая отдельный визуальный язык.\
\
Основные требования:\
\
\- Единая толщина штриха.\
\- Сдержанный размер.\
\- Цвет в соответствии с палитрой страницы.\
\- Отсутствие конкуренции с заголовками и фотографиями.\
\- Переиспользование уже подключённой библиотеки иконок.\
\
Возможная семантика:\
\
\- Travel Design — маршрут, компас или точки пути.\
\- Travel Ready — готовность, проверенный план или контрольный список.\
\- TC Trips — люди или совместная поездка.\
\- Field Notes и Archive — записи и заметки.\
\
При появлении строки иконка может плавно проявляться, немного смещаться или однократно прорисовываться по контуру.\
\
При наведении допускается короткое движение или изменение отдельной детали.\
\
Не добавляй постоянную пульсацию, бесконечное вращение и непрерывную анимацию.\
\
Не заменяй логотип Travel Club иконкой или текстовой имитацией.\

\## 10. HOVER — ссылки, CTA и строки продуктов\
\
\### Ссылки и CTA\
\
Для «Обсудить поездку», «Подробнее о форматах», «К заметкам в архиве» и других существующих ссылок:\
\
\- Стрелка слегка смещается в направлении движения.\
\- Подчёркивание плавно появляется или меняет положение.\
\- Цвет текста может немного изменяться в рамках палитры.\
\- Фон существующей кнопки может плавно менять оттенок.\
\
Продолжительность — ориентировочно 150–250 мс.\
\
Не используй сильное масштабирование, большие тени и пружинящие эффекты. Не превращай все ссылки в одинаковые массивные кнопки.\
\
\### Строки продуктов\
\
Для Travel Design, Travel Ready и TC Trips можно:\
\
\- Немного усилить цвет иконки или номера.\
\- Изменить цвет разделительной линии.\
\- Добавить сдержанную реакцию ссылки «Подробнее о формате».\
\
Если строка кликабельна целиком, её интерактивность должна быть понятна пользователю.\
\
Не добавляй скруглённые карточки и тени, если их нет в текущем дизайне.\
\
Сохрани существующие URL и действия всех ссылок.\

\## 11. NAVIGATION MOTION — нижняя навигация\
\
Нижняя навигация уже является частью интерфейса. Не перестраивай её заново.\
\
Улучши существующие состояния.\
\
\### Активный раздел\
\
\- Подчёркивание плавно перемещается к активной главе.\
\- Активное название становится визуально различимым.\
\- При необходимости номер текущей главы обновляется через короткое перекрёстное затухание.\
\- Неактивные пункты остаются читаемыми.\
\
\### Стрелки перелистывания\
\
При наведении стрелка слегка смещается в направлении движения.\
\
Сохрани корректное поведение на границах журнала и все существующие способы перелистывания.\
\
\### Обязательные условия\
\
\- Порядок глав не меняется.\
\- Прямые ссылки на развороты продолжают работать.\
\- Активный пункт всегда соответствует отображаемому развороту.\
\- Сохраняются управление с клавиатуры и видимый фокус.\
\- Не добавляй отдельную полосу прогресса, если она дублирует текущую индикацию.\
\
Навигация должна восприниматься как часть журнальной вёрстки, а не как панель управления приложением.\

\## 12. Запуск анимаций при перелистывании\
\
Это критически важная часть реализации.\
\
Новые эффекты должны запускаться после завершения существующего перехода к новому развороту.\
\
Последовательность:\
\
1\. Пользователь выбирает новый разворот.\
2\. Срабатывает существующая анимация перелистывания без изменений.\
3\. После завершения перехода активируется новый разворот.\
4\. Запускаются текстовые и графические эффекты.\
5\. Элементы появляются в согласованной последовательности.\
\
Используй существующий механизм определения активного разворота и завершения перехода, если он доступен.\
\
Не создавай параллельную систему навигационного состояния без необходимости.\
\
\### Повторное посещение разворота\
\
Если пользователь перелистнул страницу вперёд, а затем вернулся назад, поведение анимаций должно быть предсказуемым.\
\
Допускается повторное проигрывание при повторной активации разворота, если оно не раздражает и не мешает чтению.\
\
Не допускай повторного запуска из-за обычного React re-render, изменения несвязанного состояния или повторного расчёта размеров.\
\
\### Надёжность\
\
Текст не должен оставаться скрытым, если анимация не запустилась или произошла ошибка.\
\
Учитывай многострочные заголовки, переносы, кириллицу и вложенные элементы.\
\
При использовании масок текст должен оставаться полноценным текстовым содержимым страницы, доступным для копирования, поиска и вспомогательных технологий.\
\
\## 13. Производительность и доступность\
\
\- По возможности анимируй \`opacity\` и \`transform\`.\
\- Избегай постоянных циклов обновления для статичных элементов.\
\- Не допускай скачков размеров текста и блоков.\
\- Не используй тяжёлые эффекты без визуальной необходимости.\
\- Не блокируй взаимодействие до завершения второстепенных анимаций.\
\- Не скрывай важный контент навсегда, если JavaScript или анимация не сработали.\
\- Учитывай \`prefers-reduced-motion\`: при включении отключай или существенно упрощай новые необязательные эффекты.\
\- Сохраняй заметное состояние клавиатурного фокуса.\
\- Не полагайся только на hover для передачи важной информации.\
\- Проверь работу на сенсорных устройствах.\
\
Не нужно заново проектировать мобильную версию, но новые эффекты не должны нарушать существующую адаптивность.\

\## 14. Приоритеты реализации\
\
Обязательные задачи:\
