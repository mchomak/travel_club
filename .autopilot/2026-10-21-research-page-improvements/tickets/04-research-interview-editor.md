## Что должен сделать исполнитель

Исправить сброс прогресса после blur/autosave и динамически менять высоту каждого ответа с min/max. Для завершённого интервью сделать явный режим правки с кнопками «Закрыть» и «Сохранить»: закрытие возвращает на /research, сохранение создаёт новую версию. Добавить переключатель версий: последняя открыта по умолчанию, старые snapshots доступны только для чтения. В завершённом режиме не использовать обычный autosave endpoint.

Использовать CSS-module классы answerTextarea, singleLineSummary и age formatter из Т02. Не редактировать research.module.css, список, форму создания и screening-компоненты. API методы реализовать строго по interfaces.md.

## Что пользователь попросил

> «Все поля с ответами сделай динамическими, с ограничением минимальной и максимальной высоты»
>
> «Когда анкета уже заполнена и завершена и мы открываем ее вновь … должны быть кнопки "закрыть" … и "сохранить"»
>
> «в панели отображалась последняя копия с возможностью выбора версии»
>
> «Когда заполняю анкету шкала растет только пока вписываю текст, когда перестаю, она всегда отображается на нуле»

## Решения спецификации

См. разделы 3, 5–7 спецификации. Для прогресса считать заполненные значения из актуального React state после trim; blur, успешный autosave и очистка draft не сбрасывают состояние. Auto-resize ограничить заданными min/max, при превышении max включать внутреннюю прокрутку. Просмотр старой версии read-only; обычная незавершённая анкета сохраняет текущий autosave.

## Проверка

- [x] Пустой ответ после перезагрузки/blur не увеличивает прогресс; заполненный ответ сохраняет прогресс после blur и успешного autosave.
- [x] Все ответные textareas динамически подстраиваются между min/max и прокручиваются внутри после max.
- [x] Завершённое интервью открывает последнюю версию, позволяет просматривать предыдущие и не даёт менять старую версию.
- [x] «Закрыть» возвращает в список; «Сохранить» создаёт новую версию и отражает её время/номер в селекторе.
- [x] Ошибка сохранения оставляет введённые значения и показывает понятный actionable error; двойной submit предотвращён.
- [x] Frontend tests покрывают прогресс, resize и version edit/view states; lint/typecheck проходят.
