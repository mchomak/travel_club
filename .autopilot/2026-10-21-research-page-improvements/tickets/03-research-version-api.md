## Что должен сделать исполнитель

Добавить неизменяемые версии завершённых интервью. Первая версия появляется при завершении интервью; новая версия — при явном сохранении отредактированного интервью, а также при изменениях screening/category, влияющих на snapshot завершённых интервью. Snapshot должен сохранять весь набор воспроизводимых данных: respondent, screening/category, текст вопросов и ответы. Миграция создаёт версию 1 для уже завершённых интервью.

Реализовать API ровно по контракту interfaces.md. Использовать транзакции, монотонный version_number, timestamp UTC, существующие правила авторизации. Старые версии доступны только для чтения. Не разрешать обычному autosave менять ответы завершённого интервью.

## Что пользователь попросил

> «кнопки "закрыть", которая вернет обратно к списку всех респондентов»
>
> «"сохранить", которая обновит данные в анкете и пересохранит их»
>
> «чтобы в БД сохранялись версии анкет, чтобы после обновления данных, они не перезаписывались, а создавалась копия с пометкой времени обновления и новыми данными»
>
> «в панели отображалась последняя копия с возможностью выбора версии»

## Решения спецификации

См. разделы 6–7 спецификации и контракт в interfaces.md. Создавать полный snapshot; существующие completed интервью backfill как version 1. Обновление профиля/screening/category респондента создаёт новый snapshot для каждого завершённого интервью того же респондента. UI и backend принимают только полные ответы с известными question codes; сохраняют ответы и snapshot атомарно.
