# Спецификация: улучшение Research и внутренняя навигация

## Цель

Исправить поток возврата после входа, добавить закрытую стартовую страницу Travel Club и довести интерфейс Research по 13 браузерным замечаниям. Существующие данные исследовательских интервью должны оставаться читаемыми и не теряться при повторном редактировании завершённого интервью.

Основа: 24 строки из manifest.md. Ни одно требование не отложено и не снято.

## Решения и допущения

- Если переход на защищённую страницу начался без действующей сессии, после успешного входа пользователь возвращается на исходный внутренний путь вместе с query string. Внешние адреса и /admin/login не принимаются как цель. Если исходной цели нет или она некорректна, открыть /home.
- Страница /home показывает каталог всех созданных страниц проекта, включая маршруты test_12 и test_13 из активных параллельных веток. В каталоге используются их канонические относительные адреса /test_12 и /test_13; эти ссылки предназначены для общего релиза, в который войдут изменения обеих параллельных веток. Не копировать и не редактировать файлы этих страниц. До объединения ветки, где конкретного маршрута ещё нет, помечать запись «В параллельной сборке», чтобы не выдавать её за доступную в текущем preview.
- Версии относятся ко всей анкете респондента, которую показывает экран Research: полям карточки (имя/псевдоним, возраст, город, категория, статус), вступительным screening-ответам и ответам интервью вместе с текстами вопросов. Каждая версия сохраняет полный снимок этого содержимого; старые версии доступны только для чтения. Уже завершённые интервью получают начальный снимок миграцией.
- По умолчанию открыта последняя версия. Старые версии доступны только для просмотра, чтобы правка не перезаписала выбранную историю. Изменения завершённого интервью сохраняются отдельной кнопкой; незавершённое интервью сохраняет текущий autosave.
- «Городов малинников» трактуется как «городов-миллионников». Список выбора основан на актуальном официальном перечне, при этом пользователь по-прежнему может ввести любой город.
- На странице /home динамические страницы поездок и респондентов представлены ссылкой на их список; конкретная карточка открывается из этого списка.

## 1. Возврат после авторизации (R01, R06)

Файл proxy.ts для защищённых маршрутов передаёт текущий pathname и query string в серверный запрос отдельным внутренним заголовком. Он не заменяет серверную проверку сессии. requireAdmin остаётся источником авторизации: при отсутствии или истечении сессии он перенаправляет на /admin/login?next=....

Цель возврата валидируется как относительный same-origin путь: начинаться с одного /, не содержать backslash/control characters и не вести на страницу входа. LoginForm принимает next, завершает логин и заменяет историю на валидную цель. Без next используется /home. Рефреш после входа сохраняется.

Проверки: /research, /research/new, /research/{id}, /admin/trips/{id} и query string возвращают на исходный маршрут; внешняя цель и //host отклоняются; истёкшая сессия также сохраняет маршрут; URL входа не зацикливается.

## 2. Закрытая страница Home (R02-R06)

Реализовать /home и защищать её тем же серверным requireAdmin(), что и закрытые разделы. На странице собрать каталог всех уже созданных страниц проекта, сгруппированный по смысловым темам. Для каждой страницы показать название, рабочую ссылку и короткое объяснение назначения. Маршруты с параметром открывать через соответствующий список: детали поездки — после выбора поездки, анкета — после выбора респондента.

Группы каталога:
- Работа клуба: /home, /admin/trips (конструктор и список поездок; создание — /admin/trips/new; детали и клиентский просмотр открываются из поездки), /admin/account. Авторизация: /admin/login (вход в закрытые разделы).
- Исследования: /research (список респондентов), /research/new (создание анкеты), /research/[id] (профиль и интервью из списка).
- Основной публичный сайт: / (витрина палитр и шрифтов), /formats, /archive, /start, /thanks, /legal, /privacy, /personal-data, /payment, /services/route, /services/turnkey, /tours.
- Дизайн и редакционные эксперименты: /design-system и каждый маршрут /test, /test_2–/test_13. Для test_12 и test_13 добавить названия, описания и канонические ссылки как эксперименты Travel Club. До объединения параллельных веток показывать у записи статус «В параллельной сборке»; не копировать код и не менять эти ветки. В общем релизе маршруты должны разрешаться по этим ссылкам.

Каталог оформлен в текущем стиле Travel Club: светлый нейтральный фон, тёмный читаемый текст, синие акценты и системная типографика; группы разделены заголовками и спокойными строками ссылок с описаниями, без перегруженных декоративных карточек. Навигация должна быстро сканироваться, ссылки имеют заметное состояние hover/focus и доступны с клавиатуры. На узком экране группы перестраиваются в одну колонку, текст и ссылки не обрезаются.

Прямой вход на защищённую страницу до авторизации возвращает пользователя на неё после входа; если внутренний путь не задан, Home служит стартовой страницей. Страница /admin/login включена отдельной ссылкой; внешние адреса, используемые для redirect после входа, в каталог не включаются.

## 3. Список, профиль и вспомогательные подписи Research (R07–R12)

В панели поиска и фильтров выровнять подписи и контролы в общей сетке. Поле поиска не должно переносить иконку на отдельную строку; на узком viewport элементы перестраиваются в один столбец без горизонтальной прокрутки.

Название Travel Club в шапке Research остаётся одной строкой. Ссылка на Home помещается в навигацию без переноса бренда; для узкой ширины используется компактная навигация.

Строка респондента целиком открывает /research/{id}. Сохранить ссылку/фокусируемую точку входа по клавиатуре, видимый focus, понятный aria-label и семантику таблицы. Клик на вложенную ссылку не должен вызывать двойной переход.

Подписи пагинации вертикально центрируются относительно кнопок. Плашка «Все ответы анкеты (N)» и подпись дополнительного вопроса остаются в одну строку; если текст длиннее доступной ширины, использовать обрезание/ellipsis, не переносить строку и не скрывать состояние раскрытия.

Во всех экранах Research, где показывается возраст, использовать диапазон с обычным дефисом вместо подчёркивания или других тире. В таблице респондентов подпись столбца «Возраст» остаётся явной, а значение показывается как «18-22». В профиле, сводках и блоках интервью использовать подпись «Возраст: 18-22». Форматировать сохранённые коды вида 18_22 и диапазоны с другими тире только при отображении; значения в БД и логику категорий не менять.

## 4. Поля вступительной анкеты (R18–R21)

Для города проживания и города обычного вылета дать один список подсказок городов-миллионников России. Список ограничен актуальными официальными городами-миллионниками. Использовать доступную клавиатуре подсказку; не заставлять выбирать пункт из списка. Любая произвольная строка остаётся валидной и сохраняется без изменений.

Поле «Бронировали сами, с друзьями или через организатора?» становится выбором из вариантов: самостоятельно, с друзьями, через организатора, другое, затрудняюсь ответить. Для «Другое» сохранить возможность указать детали. Имеющиеся старые текстовые ответы должны отображаться и сохраняться, пока респондент не заменил их новым вариантом.

Дополнительный вопрос остаётся раскрываемым. Его подпись отображается в одну строку, длинный текст обрезается, состояние open/closed и клавиатурное управление сохраняются.

## 5. Ответы и прогресс интервью (R13, R22)

Текстовые ответы интервью автоматически подстраивают высоту под содержимое. Начальная высота вмещает несколько строк; рост ограничен комфортной максимальной высотой, после которой включается внутренняя прокрутка. Удаление текста уменьшает поле до минимальной высоты. Убрать ручной resize, не менять текст, локальные черновики, autosave, conflict handling и сообщения о сохранении.

Progress count и полоса основаны на актуальном тексте каждого ответа: ответ считается заполненным, если после trim в нём остался текст. Значение сохраняется после blur, успешного autosave и удаления локального черновика. Восстановленный серверный ответ и локальный черновик входят в расчёт; пустой ответ не считается. Значения текста не сбрасываются эффектом первичной инициализации после очистки localStorage.

## 6. Повторное редактирование завершённых интервью (R14–R17)

У завершённого интервью режим ручного редактирования:
- кнопка «Закрыть» возвращает к /research; если есть несохранённые изменения, спросить перед их удалением;
- кнопка «Сохранить» отправляет полный набор ответов и создаёт новую версию; не выполнять autosave отдельных ответов в момент ручной правки;
- версия содержит порядковый номер, время создания и полный снимок анкеты: поля профиля, screening-ответы, тексты вопросов и ответы интервью;
- последняя версия загружается по умолчанию и доступна для редактирования;
- выбор более ранней версии отображает timestamp, профиль, screening-ответы, вопросы и ответы из полного снимка только для чтения; выбор последней возвращает редактирование;
- пока есть несохранённые правки, выбор версии блокируется или требует подтвердить сброс;
- ошибки сохранения показывают понятное сообщение, текст остается на экране, кнопку можно повторить; двойной submit блокируется;
- после сохранения новая версия становится текущей, статус интервью остаётся completed, список версий обновляется.

Для незавершённых интервью сохраняется текущий посимвольный autosave и защита от конфликтов. Обычный endpoint autosave не может менять completed-интервью в обход version endpoint. Сохранение screening-анкеты или категории респондента после завершения любого интервью создаёт новый полный снимок для каждого его завершённого интервью; изменение данных и снимков атомарно. После такого сохранения список версий обновляется.

## 7. Хранение и API версий (R16–R17)

Добавить таблицу версий анкеты с UUID, interview_id, version_number, JSONB snapshot и created_at. snapshot содержит профиль респондента, поля карточки, исходные screening-ответы, тексты вопросов и ответы интервью на момент сохранения. Уникальность: (interview_id, version_number). Внешний ключ удаляет версии только вместе с самим интервью. Миграция создаёт version 1 для каждой уже завершённой записи из текущих данных респондента, research_answers и сохранённого question_snapshot, используя completed_at (или существующую дату обновления, если completed_at отсутствует).

При первом завершении нового интервью сохранить начальную версию. Создать защищённые серверной авторизацией endpoints:
- список метаданных версий интервью в обратном хронологическом порядке;
- чтение снимка одной версии;
- создание новой версии завершённого интервью.

Создание версии проверяет, что коды вопросов входят в question_snapshot, обновляет текущие ответы ResearchAnswer, собирает полное актуальное содержимое анкеты в новый неизменяемый snapshot, увеличивает revision изменённых ответов и атомарно сохраняет версию и timestamps интервью/респондента. Существующие PATCH-операции screening и категории для респондента с завершённым интервью также добавляют полный snapshot для каждого завершённого интервью в той же транзакции. При ошибке транзакция откатывается целиком. Чтение чужой версии и редактирование незавершённого через version endpoint возвращает понятное 404/409/422 без деталей стека. Финансовых или иных независимых систем в эту задачу не добавлять.
