## §3. Неприкосновенные механизмы

Начальная сцена обложки сохраняется целиком: механика появления, открытия, перелистывания, тайминги, камера, свет, последовательность, пульс/приглашение обложки и переход к первой главе. Локальные intro, capture, физический reading-turn engine и текущая подготовка/передача текстур копируются без функциональных изменений. Никакой новый эффект не применяется к обложке, opening cue, scene canvas или временным GPU/DOM листам как к навигационному UI.

Существующие фотоанимации сохраняются по механизмам, маскам, keyframes, длительностям, delays и последовательности: hero photo sweep, next aperture iris, Thai strips/people/city, China vertical/detail, archive contact prints. Не менять фото DOM, src, object-position, размеры, image masks, их data-beat или классы. Не добавлять opacity/transform/clip на содержащий фото ancestor: это фактически меняло бы фотоанимацию. Подписи можно анимировать отдельно, не затрагивая изображение. Портретные placeholders основателей остаются исходными — настоящих портретов в данных нет.

Сохраняются WebGL→live DOM handoff, готовность decode, watchdog 6 s, CSS fallback, pause в скрытой вкладке, abort/cleanup, resize/context-loss/reduced-motion interruption. Во время статичного чтения не должно быть canvas/rAF двигателя.

## §5. REVEAL: типографика

Использовать локальный clip/mask reveal на реальном текстовом блоке/внутреннем span, слева направо. Не разбивать на символы, не создавать копии текста для вспомогательных технологий, не заменять текст bitmap. Сохранить вложенные spans, br, кириллицу, пунктуацию, курсив и переносы. Маска ограничивает только визуальное появление, не меняет width/line-height/размеры блока; в финале clipping снимается или имеет достаточный безопасный inset, чтобы не резать выносные элементы шрифта.

Одна строка — 350–550 ms (ориентир 480), многострочный блок — 450–700 ms (ориентир 620), минимальные задержки между строками допустимы. Никакого медленного посимвольного печатания. Заголовок читабелен быстро, при reduced motion сразу финал.

Обязательно: «С нами в путь»; «Люди, с которых начался Travel Club»; имена Василиса и Рамиль; «Следующая история — вместе»; ARCHIVE; «Не только куда»; «Начнём с разговора». Можно также раскрывать обычные редакционные заголовки Thailand/China story. CHINA раскрывается, если не меняет фото; THAILAND оставляет исходную image-filled типографику, потому что её маски/буквы взаимодействуют с фотографиями. Большой NEXT ISSUE также может остаться исходным, чтобы сохранить композицию. Любой такой выбор сообщается в отчёте, без изменения содержания.

Длительность всей основной текстовой последовательности 0.8–1.4 s; CTA не блокируется ради ожидания. Новая система заменяет прежние долгие **текстовые** ink/rise анимации, но не меняет ни одно фото-правило и его delay. Не использовать новые text delays как глобальную замену общего data-beat: фото contact prints используют тот же beat.

## §7. DRAW

Использовать существующие thin rules, не прибавлять декоративные. Горизонталь раскрывается transform scaleX от левого края, вертикаль scaleY сверху. Допускается заменить видимую border на absolutely positioned pseudo-element с тем же цветом/толщиной, сохранив эквивалентную невидимую border для метрик. Короткие линии 200–300 ms (250), длинные 300–450 ms (380); старт привязан к своей группе, а не общий одновременный. Подчёркивание ссылки на hover/focus 150–250 ms (190). Не использовать glow/volume, не менять итоговое расположение или вес печатной линии. Static/capture/reduced state — полная линия.

## §8. ICON MOTION и HOVER

Переиспользовать установленный Lucide React и существующие Route, Sparkles, Users, Compass, MapPin, ArrowUpRight. Сохранить сдержанные размеры и согласованный line-stroke; service icons — единый штрих, стрелки своего согласованного размера. Route для Design, Sparkles для Ready (существующее «готовое путешествие»), Users для Trips. Новые archive/note icons необязательны и не должны менять композицию. Иконке достаточно одного короткого opacity/translate или stroke reveal (без изменения геометрии); при повторном hover одна короткая реакция. Без бесконечных циклов, логотип остаётся оригинальным SVG.

Ссылки «Обсудить поездку», «Подробнее о форматах», «К заметкам в архиве», все исходные CTA, head links и существующие дополнительные ссылки получают тихий отклик: стрелка 2–3 px по направлению, underline раскрывается/смещается, оттенок в прежней палитре; фон уже существующей кнопки может плавно меняться. Длительность 150–250 ms. Продуктовая строка остаётся исходной целой `<a>` с исходным aria-label/URL, курсором, focus; можно усиливать номер/иконку/линию/малый CTA. Не добавлять масштаб, большие тени, карточные скругления или массивные одинаковые кнопки. Hover стили применять с учётом hover-capability; focus-visible сохраняет видимый outline и эквивалентный отклик, важные сведения всегда читаемы без hover.

## §9. NAVIGATION MOTION

Существующая нижняя navigation, порядок семи глав, layout, labels, arrows, edge controls и состояния disabled сохраняются. Под активным пунктом находится единственный подвижный underline (одна линия вместо семи независимых вспышек), цвет и толщина прежние. Координаты измеряются относительно контейнера содержимого после layout и при resize/scroll контейнера; короткий CSS transition 220–300 ms на transform и width. Измерение не должно создавать постоянный rAF-loop; ResizeObserver/listener обновляет только при изменении геометрии и освобождается при unmount. Неактивные labels читаемы, активный label различим по цвету/весу, aria-current сохраняется. Преференс reduced motion снимает transition и сразу выравнивает линию.

Навигация читает существующие index/turn/ready, не владеет вторым индексом и не меняет navigation state machine. Во время перелистывания определить показанную главу по существующему переходу: source до handoff, destination после landing; underline/aria-current не должны заранее сообщать окончание перехода. После finish всегда совпадают с показанным разворотом. Source/target visual index вычисляется из существующего turn, не хранится как отдельное навигационное состояние. Числовой crossfade необязателен.

Стрелки previous/next и edge arrows при hover/focus сдвигают только внутренний glyph на 2–3 px в свою сторону. Сохраняются границы 1/7, disabled, клавиши ←/→, игнорирование модифицированных/повторных событий и input/contenteditable, фокус, прямые `?spread=1…7`, нормализация ошибочного/повторённого spread с сохранением остальных query, pushState/popstate/Back/Forward, возврат на обложку с сохранением главы. Не добавлять progress bar.

## §10. Запуск, повтор и fail-open

Использовать уже существующий `RevealPhase = static | pending | enter`. Владелец ready/index/turn/reveal остаётся один. Исходный callback finish срабатывает после полного ReadingTurn onComplete: leaf landed, целевые img decode завершены, live DOM имел два paint. Только он выставляет enter новой главе; introComplete делает то же после исходного вступления, direct query — в существующем mount-effect. Не менять timing и механику самого вступления/листания ради motion. Capture source остаётся static, target — pending; новые эффекты не исполняются в копиях и текстурах. Static всегда печатный финал.

Новые заголовки/каскад/линии имеют финальное видимое base CSS. В enter используется finite animation с backwards fill на время delay, без требования animationend для возврата видимости. В pending новые текстовые элементы допускается оставлять видимыми/слегка приглушёнными: важнее fail-open, чем вечный скрытый слой при ошибке JS. Старое pending фото-поведение не меняется. Если CSS animation не стартовала/отключена или компонент получил static — читаемый финал. CSS final state не зависит от таймера. Обычные re-render/hover/measurement не снимают и не добавляют enter заново. Новое посещение главы может повторить ровно одну короткую последовательность, используя уже существующий переход pending→enter и смену активного page component. Для resize/history/reduced interruption сохраняется cleanup и доступность живого текста; не добавлять state-lock ожидания secondary animations.

## §11. Доступность, производительность и адаптивность

Реальный текст остаётся доступным DOM, searchable/selectable, с исходными заголовками, aria-label, inert/aria-hidden у временных копий. Не прятать финальный/пользовательский текст от screen reader ради эффекта. Нет layout shifts, новых font loads, image fetches, libraries или API. Использовать opacity/transform; clip-path только для короткого reveal текста, с финальной безопасной геометрией. Не нужны постоянные clocks/loops для статичных элементов; observers/listeners чистятся.

`prefers-reduced-motion: reduce` отключает все новые animations/transitions на чтении, navigation и hover; сбрасывает opacity, transform, clip/mask, line scale, stroke-dashoffset к финалу, включая специфичные pending/enter правила. Проверяется как при загрузке, так и переключением preference во время enter/turn. Исходный reduced-motion skip intro/turn сохраняется. Focus-visible заметен, информация и клики доступны до завершения раскрытия, hover не является единственным носителем смысла.

Существующий TEST_12 — desktop эксперимент от ширины 1100 и высоты 700. Это часть исходной адаптивности: на 1099×900, 1440×699, 390×844 и 320×720 остаётся исходный компактный explanatory fallback со ссылкой `/test_8`. Не проектировать mobile spreads заново. Дополнительно проверить touch-capable supported desktop/tablet landscape: клики/листание не требуют hover, sticky hover не удерживает скрытый контент.

Без JavaScript сохраняется исходное доступное noscript-сообщение и ссылка на обычную версию. Новая система не ухудшает этот исходный сценарий и не скрывает fallback. Никаких изменений auth/backend/DB/env/платежей/публичных форм.

## §13. Проверки и критерии готовности

Последовательно выполнить и записать реальный результат, не использовать старые отчёты вместо новых:

1. **Шлюз копии до motion:** открыть обе версии на отдельном preview, все 7 глав; сопоставить финальные screenshots на 1440×900 и как минимум граничном desktop 1100×700; fonts/images decoded; текст/URL/геометрия совпадают, protected hashes без изменений. Сохранить evidence до следующего изменения.
2. **Качество motion:** браузерная проверка всех 7 глав; ранние/средние/финальные кадры reveal/cascade/draw, все многострочные кириллические заголовки и вложенные spans без обрезки, service row heights неизменны, единый штрих и финальная композиция соответствует control. Статические bounds минимум 1100×700, 1280×768, 1440×900, 1920×1080; unsupported/touch как в §11. Сравнивать clipping ancestors, не только bbox.
3. **Timing:** новая анимация не началась пока data-turning=true; началась после завершения leaf/handoff; в static/capture не идёт; не перезапускается от re-render/resize/hover/underline измерения; один повтор при возврате. Основная cascade укладывается в 0.8–1.4 s при неизменных более длинных фото-анимациях.
4. **Поведение:** все 7 прямых spread, неизвестный/повторённый query и сохранение unrelated query; arrow keys/previous-next/edge/contents, границы, cover+reopen, Back/Forward, видимый focus и перенос фокуса, semantic links с теми же href. Существующие capture failure/held image watchdog/context loss/resize можно проверять адаптированными новыми тестами, исходные tests не править.
5. **Контроль intro/photos:** локальные intro/capture/turn engines byte-identical с control; сравнить исходные photo CSS declarations/keyframes/delays/data attributes, включая shared beats, и визуальные кадры существующих photo effects. При необходимости сравнить один и тот же animation.currentTime в браузере: новые text-only annotations не меняют их duration/delay/keyframes.
6. **Reduced/no-motion/error:** все 7 глав и навигация читаемы при reduced motion; preference switch во время чтения/turn; CSS animation отключена → новый текст/линии видимы; noscript/fallback сохранён; нет hidden-content dead end.
7. **Инженерные проверки:** из frontend `npm.cmd run lint`, `npm.cmd run typecheck`, `npm.cmd test -- --run --testTimeout=15000`, `npm.cmd run build`; новые TEST_13 Playwright + существующие TEST_12 suite и уместные TEST_11/10 регрессии на новом изолированном runtime. Capture console/pageerror/failed requests: нет новых ошибок/битых фото. Документировать любой реально недоступный check и причину.
8. **Сохранность:** заново SHA256 всех tracked frontend из baseline и Git diff; 0 изменённых/удалённых старых файлов, shared конфигурации/packages/assets прежние. Финальный отчёт явно подтверждает TEST_12/11/10/остальные. Новые файлы локальны TEST_13, tests/scripts/evidence/docs, `.autopilot`.

Не считать задачу готовой только по первому развороту/визуальному впечатлению. Нет новых зависимостей/env/backend-модификаций. Не перезапускать чужие runtime; использовать новый изолированный dev/production preview. Deploy/publish не входят в локальную работу.

## §14. Вне рамок и открытые места

Ничего из запрошенного не отложено. Вне рамок по прямому брифу: новый контент/страницы помимо обязательной копии, смена дизайна/шрифтов/палитры/композиции, новые photo/intro/parallax эффекты, тяжёлая графика, новая навигационная архитектура. Существующие placeholders настоящих портретов остаются исходным контентом, это не новый долг TEST_13.

ASSUMPTION — принято за пользователя: проигрывать короткие новые эффекты один раз при каждой завершённой активации главы, в том числе при возврате; это прямо разрешённый брифом вариант. ASSUMPTION — принято за пользователя: сохранить существующий desktop cutoff/fallback, поскольку задача запрещает менять адаптивность. Других бизнес/вендор/платных решений не требуется. Точные milliseconds внутри указанных диапазонов — обычная реализация, не новый продуктовый scope.
