# Подготовка Geoapify для конструктора поездок

Проверено 17 октября 2026 по официальной документации. Backend интегрирован: защищённые config, поиск, обратное определение адреса, Google Maps-ссылки и маршруты. Подключение ключей выполняется локально; без них приложение честно сообщает, что провайдер не настроен. Проверки реальных маршрутов и ограничений ключей ещё не выполнены.

## 1. Аккаунт и проект

1. Откройте [Geoapify MyProjects](https://myprojects.geoapify.com/) и зарегистрируйтесь своим аккаунтом.
2. На странице **My projects** нажмите **Create a project**, назовите проект **Travel Club**.
3. Оставьте **Free**. Для начала банковская карта не требуется: 3000 credits в день, коммерческое использование разрешено с attribution. Платную подписку подключать не нужно.
4. Откройте проект → **API keys**. Первый ключ создаётся автоматически.

[Официальное начало работы](https://www.geoapify.com/get-started-with-maps-api/), [тариф и коммерческое использование](https://www.geoapify.com/pricing/).

## 2. Какие API нужны

Все запросы авторизуются ключом проекта; отдельный Google Cloud проект не требуется. Нужные endpoint-настройки и примеры доступны через **Try API** и [официальные Playgrounds](https://apidocs.geoapify.com/playgrounds).

| Задача конструктора | API Geoapify |
| --- | --- |
| Подложка интерактивной карты | [Map Tiles](https://apidocs.geoapify.com/docs/maps/map-tiles/), style.json для MapLibre либо raster tiles для Leaflet |
| Поиск названия или адреса | [Forward Geocoding](https://apidocs.geoapify.com/docs/geocoding/forward-geocoding/), до пяти результатов, без фильтра стран |
| Подпись места после выбора точки | [Reverse Geocoding](https://apidocs.geoapify.com/docs/geocoding/reverse-geocoding/) |
| Линия, километры и время каждого участка | [Routing API](https://apidocs.geoapify.com/docs/routing/) |

Категорийный Places API, Autocomplete и оптимизирующий Route Planner сейчас не вызываются. Google Maps-ссылки разбирает наше приложение: координаты выбранного места извлекаются отдельно от камеры. Если точку извлечь нельзя, нужно подтвердить поиск по названию или поставить пин вручную. Поддержаны HTTPS Maps-домены Google `.com`, `.ru`, `.co.uk`, `.de`, `.fr`, `.co.jp` и короткие `maps.app.goo.gl`, `goo.gl/maps/`; другие домены не загружаются. Короткие ссылки раскрываются до трёх переходов только по allowlist; private IP и credentials запрещены, HTML не скачивается для поиска точки.

## 3. Отдельные ключи для карты в браузере и backend

В **API keys → Create a new API key (+)** подготовим **Travel Club Web** и **Travel Club Backend** с отдельными ограничениями. [Официальная инструкция по ключам](https://myprojects.geoapify.com/help/api-keys/).

- **Ключ браузера:** **Allowed origins** — `http://localhost:3000` для разработки и публичный origin сайта, который видит партнёр, например `https://travel.example.com` или `http://PUBLIC_IP:PORT`, если сайт открывается по IP и порту. Добавляйте `http://localhost:3001` только если используете этот dev-порт. `localhost` означает компьютер каждого посетителя и не является адресом вашего сервера. Альтернатива — **Allowed HTTP referrers**: поле поддерживает regex, поэтому Google-шаблоны со звёздочкой вслепую не копировать.
- **Ключ backend:** **Allowed IP addresses** — настоящий стабильный публичный исходящий IP той машины, где работает backend (в вашем случае обычно сервер). Публичный адрес сайта и исходящий адрес сервера могут совпадать, но это нужно проверить с сервера; `localhost` и внутренний IP Docker не подходят. IP локального ПК добавляйте только если backend-запросы при разработке действительно отправляются с этого ПК, и указывайте его публичный исходящий адрес, не `192.168.x.x` / `10.x.x.x`. Если egress IP неизвестен или меняется, пока не включайте IP-ограничение; ключ нужно хранить только на backend и не публиковать.
- **CORS Access-Control-Allow-Origin** само **не защищает ключ**; нужны ограничения доступа выше.

Браузерный ключ виден в запросах; серверный хранится секретно. Ограничения проверим реальными запросами. [Защита ключей](https://myprojects.geoapify.com/help/api-keys/).

## 4. Локальный .env и запуск

В корне репозитория откройте существующий `.env` локальным редактором. Если файла ещё нет, сначала выполните `python scripts/init_env.py`. Добавьте две строки и вставьте соответствующие значения непосредственно в файл:

```dotenv
GEOAPIFY_API_KEY=
GEOAPIFY_MAPS_API_KEY=
```

Первое значение — **Travel Club Backend**, второе — **Travel Club Web**. Пустые строки допустимы. `.env` не коммитится; `.env.example` содержит только пустые новые поля. Переменных `NEXT_PUBLIC_*` для ключей нет: browser key приходит после входа через `GET /api/maps/config`, серверный ключ не возвращается.

При первом обновлении кода из корня PowerShell:

```powershell
docker compose up -d --no-deps --build --wait backend
```

После изменения только ключей пересоздайте backend, чтобы Compose перечитал env:

```powershell
docker compose up -d --no-deps --force-recreate --wait backend
```

`docker compose restart` не подхватывает изменённые переменные. Frontend из-за смены ключей пересобирать не нужно. Не выводите `docker compose config`, `docker inspect` или окружение контейнера в чат: они могут раскрыть секреты.

Для будущего серверного запуска имена те же, но используйте отдельные production keys и утверждённый публичный HTTPS origin. `compose.deploy.yaml` подключает только backend к `maps_egress`, чтобы разрешить исходящие DNS/HTTPS-запросы; PostgreSQL и frontend остаются в внутренней сети `app`, новых опубликованных портов нет. Это подготовка конфигурации, не выполненный deploy.

## 5. Проверка подключения

1. Войдите в закрытый конструктор. В DevTools → Network посмотрите `/api/maps/config`: `maps_key` должен быть заполнен browser key, `search_enabled` и `routing_enabled` — `true`. Не пересылайте сам ответ или screenshot с ключом.
2. Запрос поиска `/api/maps/search?q=Paris` из текущей авторизованной сессии должен вернуть `places`; reverse принимает `latitude`/`longitude`. Без входа любой `/api/maps/*` возвращает 401. Без backend key search/reverse/route возвращают 503 с `provider_not_configured`.
3. Для проверки backend маршрута отправьте из авторизованной сессии `POST /api/maps/route` с JSON `{from: MapPlace, to: MapPlace, mode: "drive"|"walk"|"transit"}` и заголовком `X-Requested-With: TravelClub`; Origin должен совпасть с сайтом. Используйте два выбранных места. Успех: `status:"ok"`, метры, секунды, GeoJSON LineString. `unavailable` и null вместо цифр означают отсутствие данных, а не нулевой путь.
4. Подложку проверьте в браузере с действующего origin. Для raster-карт браузер должен отправлять разрешённый referrer/origin; CORS-заголовок сам не ограничивает расход ключа. Ошибки 401/403 Geoapify обычно требуют проверки ключа/ограничений; 429 — квоты/частоты. Backend выдаёт безопасную ошибку, без provider payload.
5. В проекте Geoapify откройте Statistics, проверьте активность отдельно по Web и Backend. Проверьте, что запросы с разрешённого origin и исходящего IP проходят, а с неразрешённого — отклоняются. На сервере это проверяется только после отдельного разрешённого deploy.

При отсутствии ключей ручные координаты, сохранение мест и локальный разбор полных Google URL остаются доступны. Не выдавайте этот режим за успешную live-проверку. Автотесты используют HTTP fixtures только в тестах.

## 6. Подписи на карте

На Free сохраняем видимые ссылки **Powered by Geoapify**, **© OpenStreetMap contributors**, а для стилей на схеме OpenMapTiles — также **© OpenMapTiles**. `style.json` содержит attribution; не скрываем стандартный блок. Для raster/Leaflet подписи задаются явно в интеграции. [Точные требования Map Tiles](https://apidocs.geoapify.com/docs/maps/map-tiles/).

## 7. Контроль квоты и транспорт

В проекте открывайте **Statistics** и смотрите одновременно запросы и **credits**, включая разбивку по ключу. Второй ключ не даёт ещё 3000 credits. [Помощь MyProjects по проектам](https://myprojects.geoapify.com/help/projects/), [ключи и общий лимит](https://myprojects.geoapify.com/help/api-keys/).

Карта тоже расходует запас: tile = 0.25 credit; autocomplete/geocoding = 1; базовый routing = число промежутков между точками, плюс доплаты для длинных маршрутов и дополнительных параметров. [Расчёт credits](https://www.geoapify.com/pricing-details/). На Free заявлено до 5 requests/sec; суточный предел мягкий, поэтому не считаем его гарантированной автоматической остановкой. [Правила тарифа](https://www.geoapify.com/pricing/).

Для `drive`/`walk` backend использует одноимённые профили. Для транспорта сначала запрашивается `transit`. Только пустой ответ маршрутов запускает второй запрос `approximated_transit`, с явным сообщением о приближении; timeout, 429 и другие ошибки не повторяются. `bus` не используется: это профиль движения автобуса по дорогам, а не общественный транспорт. Все transit-оценки помечаются `approximate:true`, расписание на дату поездки не передаётся и не гарантируется. [Профили и формат ответа Routing](https://apidocs.geoapify.com/docs/routing/).

До регулярной работы проверьте качество реальных маршрутов клуба, включая Китай. Покрытие транспорта зависит от доступных данных; отсутствие пути не превращается в 0 км или прямую линию. [Routing FAQ](https://www.geoapify.com/routing-api/).
