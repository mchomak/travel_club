# ADR 0004: Частный кабинет и клиентский просмотр с явным списком полей

Статус: принято. Основание: `spec.md` §§4–5, 16, 19, 21 и уточнение G2.

## Контекст

В одном рабочем маршруте находятся клиентские описания и заметки, внутренние инструкции, закупочные цены, курсы и прибыль. Просмотр для клиента нужен организатору, но случайный вывод приватных полей даже в JSON ответа раскрывает внутреннюю экономику. Кабинет не предусматривает публичную регистрацию.

## Решение

- Административные страницы защищаются серверной проверкой Next, а каждый частный API — самостоятельной серверной проверкой сессии. У администратора отдельный локальный bootstrap; пароли хранятся как Argon2id-хеши. Сессия хранит SHA-256 digest случайного токена, истекает через 12 часов и отзывается при logout. Cookie HttpOnly, SameSite=Lax и Secure в production.
- Небезопасные HTTP-методы требуют `X-Requested-With: TravelClub`, а присутствующий `Origin` сверяется с настроенным origin; чужой CORS не разрешается. Попытки входа ограничиваются персистентно по логину и IP без доверия произвольному `X-Forwarded-For`.
- `GET /api/trips/{id}/preview` возвращает отдельную строгую allowlist DTO: клиентское название (или fallback), даты, участников, местоположения, дни и нефинансовые элементы с временем, описанием и `client_note` на уровнях поездки, дня и элемента. Общие элементы показываются отдельно. Endpoint остаётся внутри защищённого кабинета; публичной ссылки нет.

## Почему (отклонённые альтернативы)

Только клиентская проверка авторизации не защищает API при прямом запросе. Публичная ссылка или сложная ролевая модель не нужны для текущей внутренней работы. Удаление приватных полей только перед рендерингом оставляет их в сетевом ответе и состоянии браузера; поэтому отвергнут прямой вывод полного `TripDocument` в preview. Исключить все заметки тоже неверно: G2 требует клиентские заметки на трёх уровнях.

## Последствия

Preview не содержит `internal_note`, цен, курсов, себестоимости, наценки или прибыли ни в DTO, ни в DOM; редактируемые данные не становятся источником клиентского экрана. Проверки безопасности охватывают прямые URL/API, logout, ограничения входа, Origin/CSRF и редактирование без сессии. Печать preview не должна раскрывать элементы кабинета.
