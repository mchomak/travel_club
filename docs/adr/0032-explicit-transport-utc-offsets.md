# ADR 0032: Ручные смещения UTC у переездов

## Контекст

Местные дата и время отправления и прибытия не определяют длительность рейса через часовые пояса или линию перемены дат. Существующие поездки уже используют местное время, поэтому их расписание должно сохраниться.

## Решение

Для дальнего переезда хранить пару nullable-полей со смещениями UTC в минутах для каждого конца маршрута. Оба смещения задаются вручную для даты события; календарь продолжает показывать местное время, а длительность рассчитывается по UTC. Добавить поля без заполнения для старых строк: два `NULL` сохраняют прежнее поведение.

## Почему

Считать оба конца в одной зоне или выбирать зону по городу нельзя для перелётов между часовыми поясами и через линию перемены дат. Именованные зоны потребовали бы базы IANA и автоматических правил летнего времени, которых приложение сейчас не использует; угадывание зоны могло бы незаметно изменить сохранённое расписание. Пара nullable-смещений позволяет явно вычислить длительность и оставить прежние записи без догадок.

## Последствия

Форма и сервер проверяют, что заданы оба смещения, их диапазон не шире ±14 часов и длительность по UTC положительна. При переносе события календарь сохраняет реальную длительность и смещение прибытия. За правильный offset для конкретной даты отвечает редактор; автоматического определения зоны и перехода на летнее время нет.
