# ADR 0023 — TC Research как модуль приложения с общей admin-сессией

## Контекст

TC Research задан как отдельная внутренняя зона /research и API /api/research, но спецификация предписывает использовать текущие Next.js, FastAPI, SQLAlchemy и PostgreSQL. Страница и каждый API-маршрут должны проверять существующую admin-сессию; новые роли и пароли не нужны (spec §§1, 5, 11; manifest R01–R08, R63–R64).

## Решение

Реализовать Research отдельным модулем в существующем приложении и защищать страницу и API текущей admin-сессией. Не вводить отдельный сервис или вторую схему аутентификации.

## Почему

Самостоятельный сервис и отдельная Basic Auth пара потребовали бы второго контура доступа, тогда как выбранная спецификацией граница уже отделяет Research по маршрутам и модулю, сохраняя общий стек. Существующая сессия прямо указана как предположение, подходящее двум основателям.

## Последствия

Research остаётся закрытым для пользователей без текущей admin-сессии, а его интерфейс и API развиваются в своих модулях. Развёртывание и база данных остаются общими с приложением.
