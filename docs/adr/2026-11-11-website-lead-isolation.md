# ADR: Изоляция заявок Website

- Статус: принято
- Дата: 2026-11-11

## Контекст

Публичная форма принимает персональные данные. Их требуется отделить от данных Constructor, Interviews и остальных внутренних систем. Спецификация также требует независимые credentials, минимальные права, отсутствие прямого доступа из браузера и сохранение заявки вместе с задачей уведомления без потери при сбое Telegram.

## Решение

- Обслуживать `/api/leads/**` отдельным FastAPI-процессом с собственными credentials. Gateway направляет этот префикс только в него; процесс не получает адреса или учётные данные внутренних баз.
- Хранить заявки и outbox в отдельной PostgreSQL-базе Website. Runtime-роль получает только необходимые права на её таблицы; миграции Website выполняются отдельным набором миграций и отдельными миграционными credentials. Runtime не использует superuser и не может менять роли или базы.
- Записывать заявку и задачу уведомления одной транзакцией. Отдельный обработчик доставляет уведомления и повторяет временно неудачные попытки; по умолчанию Telegram получает только номер и продукт.

## Последствия и компромиссы

Изоляция ограничивает доступ между продуктами и радиус утечки, сохраняя возможность разместить отдельную базу в существующей PostgreSQL-инфраструктуре. Отдельные база, роли, credentials и миграции добавляют настройки развёртывания, секреты, резервное копирование и отдельный путь обновления схемы. Outbox обеспечивает надёжную повторную доставку, но при неопределённом результате сетевого запроса уведомление может прийти повторно. Отдельный PostgreSQL-инстанс не обязателен, если изоляция базы, ролей и сети достаточна.
