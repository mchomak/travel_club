# ADR 0003: Ручные курсы и воспроизводимая историческая стоимость

Статус: принято. Основание: `spec.md` §§10–12, 20, 23 и границы продукта; `manifest.md`, самобрифинг.

## Контекст

Статьи поездки могут быть в разных валютах, а итог имеет одну базовую валюту. Для внутренней сметы нужно объяснимое направление курса и возможность позже воспроизвести именно тот расчёт, который был сохранён. Автоматические тарифные или валютные API в текущий объём не входят.

## Решение

- Для поездки сохраняются вручную введённые положительные курсы трёхбуквенных валют. Курс означает стоимость **одной единицы валюты статьи в базовой валюте поездки**; у базовой валюты курс всегда 1. Для иностранной валюты без курса расчёт и сохранение завершаются понятной ошибкой, а не догадкой.
- Для каждой статьи сохраняются исходная стоимость, исходная валюта, использованный курс и нормализованная стоимость. Изменение курса транзакционно пересчитывает снимки и агрегаты по правилам ADR 0001.
- При смене базовой валюты прежние значения курсов не трактуются как курсы к новой базе. Пользователь заново вводит или подтверждает все необходимые направления, включая прежнюю базовую валюту, если в ней остались статьи.

## Почему (отклонённые альтернативы)

Подстановка курса 1 для неизвестной валюты создаёт убедительный, но ложный итог. Хранение только нормализованной суммы уничтожает проверяемую историю расчёта; хранение только текущего глобального курса меняет смысл прошлых смет. Внешний FX API усложняет воспроизводимость, вводит зависимость от сети и выходит за пределы MVP. Автоматическое повторное применение старых чисел после смены базы путает направление конверсии.

## Последствия

UI явно показывает направление каждого курса и позволяет собственный код `[A-Z]{3}` помимо подсказок распространённых валют. Серверная валидация проверяет отсутствие пропусков и допустимые границы `NUMERIC`. Исторический документ остаётся проверяемым по своим снимкам, даже когда пользователь позже обновляет курсы новой редакции поездки.
