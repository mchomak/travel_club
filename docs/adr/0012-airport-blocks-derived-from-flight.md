## Контекст

Перелёт требует заранее показать приезд в аэропорт и время выхода после прилёта. Эти интервалы должны следовать за рейсом при переносе и исчезать при удалении, но администратор может настроить каждый интервал вручную.

## Решение

Хранить на перелёте две длительности в минутах: `airport_before_minutes` и `airport_after_minutes`, по умолчанию 180 и 60. Календарь строит из них два производных блока относительно вылета и прилёта. Правка блока меняет соответствующую длительность на перелёте; значение 0 скрывает блок. Локальные часы берутся из расписания без вывода часовых поясов. За пределами дат поездки отображается только попавшая внутрь часть интервала. Блоки не являются самостоятельными платными пунктами.

## Почему

Рассмотрены два отдельных сохраняемых события со ссылкой на рейс. Этот вариант отвергнут: перенос и удаление потребовали бы синхронизации трёх записей, а расчёт мог бы ошибочно учесть подготовительные блоки как новые расходы. Длительность на рейсе сохраняет индивидуальную настройку при его переносе.

## Последствия

Создание, перенос и удаление рейса автоматически меняют связанные блоки без каскадного обновления записей. Интервалы не влияют на цену. Календарь отвечает за построение и обрезку блоков, а API валидирует допустимый диапазон длительностей.
