# ADR 0022 — Исходящая сеть только для backend

## Контекст

План карт предполагает внешние HTTP-запросы backend к провайдеру. Зафиксированное отклонение D01: deploy Compose с сетью `internal: true` блокирует такой исходящий доступ (spec §5; manifest D01).

## Решение

Подключить только backend к дополнительной non-internal bridge-сети для исходящего доступа, сохранив его подключение к исходной закрытой сети. PostgreSQL остаётся только во внутренней сети. Новых опубликованных портов не добавлять; это подготовка конфигурации, фактический удалённый deployment отложен согласно R22.

## Почему

Backend необходим внешний доступ для предусмотренного HTTP-взаимодействия, тогда как базе данных он не требуется. Дополнительная сеть устраняет препятствие провайдерным запросам без снятия сетевой изоляции PostgreSQL и без нового входящего интерфейса.

## Последствия

Backend получает более широкую возможность исходящих соединений: сама bridge-сеть не ограничивает их одним провайдером. При будущем развёртывании потребуется проверить реальный исходящий доступ и server-origin ограничения; подготовленная конфигурация не доказывает их работоспособность на сервере. Изоляция базы сохраняется, но backend остаётся участником обеих сетей.
