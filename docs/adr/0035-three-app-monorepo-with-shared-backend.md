# ADR 0035 — Три frontend-приложения с общими backend и origin

## Контекст

Репозиторий содержит три продукта с разными маршрутами, интерфейсами и темпом развития. Одновременно конструктор и Interviews используют существующие API FastAPI, PostgreSQL, миграции Alembic и административную сессию. Сессионная cookie host-only, поэтому разнесение этих интерфейсов по разным origin потребовало бы отдельного решения для SSO и межсайтовых запросов. Требования: R03, R50, R66, R68, R74, G02; прежнее решение о модульном монолите — ADR 0005, решение об общей admin-сессии TC Research — ADR 0023.

## Решение

Развивать Website, Trip Constructor и Interviews как три самостоятельных Next.js-приложения в одном репозитории. Каждое приложение владеет своими маршрутами, настройками, ресурсами, глобальными стилями и дизайн-системой; визуальные компоненты, шрифты и токены между приложениями не импортируются.

Оставить один FastAPI backend, одну PostgreSQL и одну историю миграций Alembic. Backend остаётся единственным источником API, авторизации, данных и бизнес-правил. Общий origin обслуживается path-based gateway: публичные пути направляются в Website, `/admin/**` и `/home` — в Constructor, `/research/**` — в Interviews, `/api/**` — в backend. Gateway передаёт cookie и семантику запросов; он не заменяет проверки доступа в приложениях или backend.

## Почему

Так граница независимого развития проходит между frontend-продуктами, а не между копиями backend, схемы данных и auth. Общий origin сохраняет существующую host-only сессию и same-origin запросы; отдельные сборки остаются независимыми. Этот выбор не вводит новую систему идентификации или дополнительные базы.

## Последствия

- Изменения визуальной системы одного приложения не распространяются через импорты на два других.
- Каждое приложение можно запускать и собирать отдельно; маршрутизатор нужен для общего origin и переходов между продуктами.
- Backend/API, auth, PostgreSQL и миграции остаются единственными и общими. Проверки их доступа и бизнес-логики сохраняются.
- Будущее размещение на разных origin потребует отдельного ADR о cookie, CSRF, CORS и межпродуктовом входе; это решение не подразумевает SSO между разными доменами.

## Открытия при реализации

В манифесте этой реорганизации нет строк `D##`; в данном ADR не зафиксированы новые ограничения, выведенные из реализации.
