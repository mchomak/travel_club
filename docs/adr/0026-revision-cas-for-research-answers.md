# ADR 0026 — CAS по revision для сохранения ответов

## Контекст

Ответы автоматически сохраняются после debounce и потери фокуса. Клиент отправляет ожидаемую revision; равный повтор должен быть идемпотентным, а устаревшая запись — получать 409 и не затирать новый ответ. Локальный текст сохраняется до серверного подтверждения и при сетевой ошибке (spec §§2, 5–7; manifest R42–R46, R56).

## Решение

Сохранять каждый ответ с положительной revision и выполнять запись по compare-and-swap с expected_revision. Повтор той же записи допускается идемпотентно; при несовпадении revision сервер возвращает конфликт, а клиент сохраняет локальный текст до явного разрешения.

## Почему

Last-write-wins позволил бы запоздавшему запросу молча заменить более новую версию. Одного локального черновика недостаточно для подтверждения серверного сохранения и восстановления после повторного открытия. CAS делает конфликт видимым и не удаляет локальный текст, нужный для его разрешения.

## Последствия

Интерфейс должен различать локальный черновик и подтверждённое серверное сохранение, а конфликт — предлагать сохранить локальный текст с актуальной revision.
