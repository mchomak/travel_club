## Контекст

Редактор повторно сохраняет загруженный `TripDocument` через преобразование в `TripInput`. Добавленные `subtype` и длительности аэропорта могут успешно записаться в базу, но пропасть при следующем сохранении, если преобразование их не передаст (D02).

## Решение

Считать преобразование сохранённого документа обратно в редактируемый ввод полным для всех сохраняемых полей пункта. Передавать `subtype`, `airport_before_minutes` и `airport_after_minutes` через существующий `tripInput` и `DraftSession`. Проверять повторное сохранение без изменения этих полей регрессионным тестом.

## Почему

Рассмотрено отдельное локальное состояние для новых полей с частичным PATCH при сохранении. Оно отвергнуто: появятся два источника данных и особый путь автосохранения, несовместимый с уже используемым контролем версии поездки.

## Последствия

Повторное сохранение не стирает подвид и ручную настройку аэропорта. При добавлении следующих сохраняемых полей пункта преобразование документа в ввод нужно проверять вместе с API и базой; иначе возможна тихая потеря данных.
