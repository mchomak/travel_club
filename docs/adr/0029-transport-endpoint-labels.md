# ADR 0029: Отдельные названия конечных точек транспорта

## Контекст

R15–R17 требуют независимо сохранять «Откуда» и «Куда»,
включая собственные названия без адреса и координат.
По D01 одна строка `location` не выражает эти два значения;
существующие снимки мест нужны для карты и расчёта пути.

## Решение

Добавить `departure_label` и `arrival_label` длиной до 200 символов
рядом с существующими снимками мест. Для старых записей — пустые значения.
Сохранить `location` без разбора и потери исходного текста.
Название без привязки допустимо; оно не задаёт координаты для маршрутизации.
Повторно выбирать места только из текущей поездки.

## Почему

Разбор общей строки по разделителю неоднозначен: разделитель может входить
в название, а назначение частей старого текста неизвестно.
Обязательная геопривязка исключила бы разрешённый ручной ввод.
Глобальный каталог потребовал бы правил общего владения и обновления адресов,
которых текущая задача не задаёт.

## Последствия

Понадобятся миграция, валидация и сохранение обоих полей при копировании поездки.
Форма должна ясно отличать название без адреса от подтверждённого места.
Поддержка старого `location` и новых полей сохраняет нагрузку совместимости;
автоматический расчёт недоступен, пока обе точки не определены.
