# ADR 0002: Атомарный документ поездки, версия и безопасное сокращение дат

Статус: принято. Основание: `spec.md` §§6–8, 16–18, 20–23; `manifest.md`, самобрифинг.

## Контекст

Маршрут меняется целиком: дни, порядок элементов, размещение по дням, курсы, заметки и расчёт связаны между собой. Автосохранение и две открытые вкладки способны отправлять конкурирующие версии. Сокращение диапазона дат потенциально удаляет заполненные дни и услуги, а потеря сети не должна стирать черновик.

## Решение

- `PUT /api/trips/{id}` принимает полный редактируемый `TripInput` с `version`. Сервер в одной транзакции проверяет принадлежность UUID, согласует дни с включительным диапазоном дат, пересчитывает смету и сохраняет агрегат в нормализованных таблицах PostgreSQL. Успешный ответ содержит актуальный документ, расчёт и новую версию.
- Расширение периода добавляет пустые даты; сокращение оставляет пересечение и удаляет пустые дни. Если удаляются заполненные дни либо элементы, сервер возвращает `409 DATE_REMOVAL_REQUIRED` со списком дат и ждёт повторный запрос `confirm_date_removal=true` после явного согласия человека. Отсутствие дня в присланном массиве не считается таким согласием. Проживание, выходящее за новый период, требует исправления или подтверждённого удаления; ночи не обрезаются незаметно.
- Несовпадение `version` возвращает `409 VERSION_CONFLICT` без записи. UI сохраняет локальные поля, сообщает о конфликте и предлагает перечитать данные с предупреждением о потере несохранённого. Автосохранения сериализованы и используют версию последнего успешного ответа; поздний ответ не заменяет более свежий ввод. Preview открывается только после успешного актуального сохранения.

## Почему (отклонённые альтернативы)

Набор независимых endpoint для каждого дня, курса и элемента допускает промежуточно несогласованную смету. Хранение поездки одним JSON blob лишает базу ограничений связности и адресных миграций. Последняя запись без проверки версии молча затирает другую вкладку. Автоматическое удаление заполненных дат по одному сокращению диапазона противоречит защите бизнес-данных; молчаливое продление или обрезка гостиничных ночей меняет стоимость.

## Последствия

Клиент должен держать локальный черновик и честные состояния «Есть изменения», «Сохранение…», «Сохранено», «Не удалось сохранить», а также явный повтор. Сервер отвечает за транзакционную целостность и проверяет отдельный флаг подтверждения на каждом потенциально разрушительном изменении. Повторное открытие восстанавливает данные, порядок, курсы и финансовые снимки; копирование создаёт независимые UUID.
