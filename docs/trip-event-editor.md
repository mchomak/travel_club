# Редактор событий поездки

Документ описывает устройство кода на момент просмотра рабочего дерева. Он служит внутренней картой для разработки, а не подтверждением готовности интеграции или полного совпадения поведения форм. Старой формой ниже называется ветка `ItemForm` без `playgroundCompact`, компактной — ветка с этим флагом. Проверка здесь — чтение исходников и имеющихся тестов; тесты и браузерные сценарии при составлении документа не запускались.

## Слои и поток данных

- `src/lib/contracts.ts`: `ItemInput`, `EventStage`, типы и подтипы; `trip-ui.ts`: категории, соответствия старых типов, подписи и режимы расчёта по умолчанию.
- `trips/item-form.tsx`: единый `react-hook-form` и `FormProvider`, выбор типа и подтипа, преобразование значений, локальная валидация и предварительный `calculateTrip`. Обе формы передают результат через один `onSubmit(item, rate?)`. Сервер остаётся источником авторитетного финансового расчёта.
- `event-playground/compact-editor.tsx`: сводка и секции компактной формы. Содержимое маршрута, расписания, стоимости, ссылок и дополнительных настроек передаётся из `ItemForm`; форма не создаёт отдельную модель данных. `EditorSection.fields` связывает ошибки верхнего уровня с подписью секции.
- `PlaygroundRoute`, `PlaygroundSchedule` / `PlaygroundHotelSchedule`, `CostSection`, `LinksFields`, `CompactStages` реализуют содержимое. Общие элементы включают `GeographicPoint`, `MultilineField`, `Field` и контекст `CompactFieldHints`. Старая ветка использует `FlightEditor`, `ExcursionEditor` либо `EventRouteSection` / `EventScheduleSection`, а также общие секции стоимости и заметок.
- `trip-editor.tsx` передаёт `playgroundCompact` для inline и панели и после submit обновляет черновик поездки и, при необходимости, курс; сохранение события в форме само по себе не доказывает запись поездки на сервер. `event-playground.tsx` хранит результат локально в песочнице. Сквозная запись и повторное открытие здесь не проверены.
- При редактировании существующего элемента `ItemForm` накладывает только изменённые поля на исходный объект, чтобы сохранить отсутствующие необязательные и исторические значения; новые элементы проходят нормализацию. Для проживания даты могут синхронизировать день и длительность. Курс передаётся отдельно и относится ко всей поездке.

## Матрица типов и подтипов

Все строки ниже — соответствие по коду, без утверждения об идентичности UX и сквозной сохранности. Общие поля приведены в следующей таблице. Подтипы перечислены значениями контракта; пустой подтип также возможен у исторических данных.

| Сохранённый `type` | Категория / подтипы | Старая форма | Компактная форма и оговорки |
|---|---|---|---|
| `flight` | Перелёт; отдельных вариантов нет | `FlightEditor`, включая аэропорты и UTC | Общие маршрут и расписание; поля аэропорта вложены в расписание. Проверить переход типа и UTC в браузере. |
| `train_bus` | Транспорт; исторический пустой подтип либо варианты транспорта | Общая форма | Маршрут и расписание транспорта; пустой подтип сохраняет историческую подпись. |
| `transfer` | Транспорт: `bus`, `train`, `taxi`, `car`, `walk`, `rental`, `water`, `other` | Общая форма | Общий маршрут транспорта; в контексте `long-haul` новые `taxi` и `walk` скрыты, исходный подтип остаётся доступен. |
| `rental` | Транспорт; по умолчанию отображается `rental` | Общая форма | Категория выводится через `eventCategory`, фактический тип следует проверять при смене подтипа. |
| `hotel` | Проживание; отдельных вариантов нет | Общая форма, выбор объекта, расписание проживания | `PlaygroundHotelSchedule`; этапы доступны только если уже существуют. Даты и режим влияют на расчёт ночей. |
| `excursion` | Впечатления; отображается `excursion` | `ExcursionEditor` | Общие секции и `CompactStages`. |
| `activity` | Впечатления: `excursion`, `activity`, `other` | `ExcursionEditor` для `excursion`, иначе общая форма | Общие секции и `CompactStages`. |
| `meal` | Еда: `restaurant`, `cafe`, `bar`, `street_food`, `other` | Общая форма | Общие секции и `CompactStages`. |
| `insurance` | Допрасход; отображается `insurance` | Общая форма | Общие секции и `CompactStages`; не входит в обычный список `eventCategories`. |
| `other` | Допрасход: `insurance`, `sim`, `communication`, `visa_fee`, `service_fee`, `other` | Общая форма | Общие секции и `CompactStages`; добавление допрасхода следует проверять через соответствующий сценарий конструктора. |

## Матрица полей

«Код» означает, что поле или его путь обнаружен в исходниках; это не результат выполнения теста. Условные поля показываются по типу, режиму или состоянию. Для всего перечня необходимо отдельно проверить редактирование, отмену, сохранение и повторное открытие.

| Данные `ItemInput` | Старая форма → компактная | Источник и сохранение | Доказательство / ограничение |
|---|---|---|---|
| `type`, `subtype` | Выбор типа и подтипа → меню категории и дополнительные настройки | `trip-ui.ts`, `ItemForm`; значения в `onSubmit` | Код; смена типа перелёта требует подтверждения. Полная матрица переходов не проверена. |
| `title`, `location`, `map_place`, `map_end_place` | `EventRouteSection` или специализированная форма → `PlaygroundRoute`, `GeographicPoint` | Форма и места поездки; изменённые поля в элементе | Код; поведение всех географических вариантов не подтверждено E2E. |
| `departure_label`, `arrival_label`, `departure_country_code`, `arrival_country_code`, `departure_city`, `arrival_city` | Поля маршрута / перелёта → `PlaygroundRoute`, `CountryCity` для перелёта | `ItemInput`; метки и выбранные точки меняются через `setValue` | Код; доступность конкретного поля зависит от типа. |
| `day_id`, `end_day_id`, `start_time`, `end_time`, `departure_utc_offset_minutes`, `arrival_utc_offset_minutes` | `EventScheduleSection` / поля перелёта → `PlaygroundSchedule` | Дни поездки и форма; проверка порядка и UTC в `ItemForm` | Код; тесты расписания существуют, в этой работе не запускались. |
| `check_in`, `check_out`, `check_in_time`, `check_out_time` | Расписание проживания → `PlaygroundHotelSchedule` | Даты поездки и форма; изменение дат может пересчитать `day_id` и `duration_days` | Код; regression-тесты описывают неизменённую длительность и пересчёт после изменения дат, не запускались. |
| `airport_before_minutes`, `airport_after_minutes` | Поля перелёта → `FlightAirportFields` в расписании | `ItemInput`; значения по умолчанию в `ItemForm` | Код; доступно для перелёта. |
| `calculation_mode`, `unit_price`, `currency`, `quantity`, `price_pending`, `included`, `participants_override`, `capacity`, `rooms_override`, `duration_days` | `CostSection` → тот же `CostSection` с `compact` | Элемент; курс — отдельное состояние, передаётся вторым аргументом `onSubmit` | Общая реализация по коду; режимы и условные поля требуют проверки на каждом типе. |
| `external_url`, `map_url`, `booking_url`, `publish_external_url` | `LinksFields` в поддерживаемых старых секциях → `LinksFields` в компактной | Элемент; пустые URL нормализуются в `null`, проверяется URL | Код; наличие поля в старой форме зависит от типа. |
| `description`, `client_note`, `internal_note` | `NotesSection` → `MultilineField` в двух секциях | Элемент; внутреннюю заметку не следует показывать клиенту | Код; клиентский вывод и приватность не проверялись. |
| `stages`: `id`, `title`, `start_time`, `end_time`, `location`, `address`, `map_url`, `notes` | `EventStagesSection` / специализированная форма → `CompactStages` | Массив элемента; обязательное название и URL валидируются в форме | Код; есть regression-тесты добавления этапа для `meal` и `insurance`, а также навигации к ошибке, не запускались. |
| `id`, `position`, `auto_transfer` | Прямого общего поля ввода нет | Приходят из исходного элемента / конструктора; позиция может меняться при переносе дня | Код сохранения; нельзя считать эти поля редактируемыми в форме. |

## Расширение

1. Для категории сначала согласуйте модель и допустимые значения с контрактом и backend. Затем проверьте `itemLabels`, `eventCategories`, `eventCategory`, `subtypeOptions`, `defaultModes` и создание элемента в `trip-ui.ts`; учтите исторические типы и ограничения `long-haul` в `ItemForm`. Добавление пункта только в select не создаёт поддержку сохранения или расчёта.
2. Для секции добавьте содержимое через существующий `FormProvider` и передайте его из `ItemForm` в `CompactEditor`. Укажите поля в `EditorSection.fields`, сводку и стабильный идентификатор секции; проверьте навигацию к ошибкам, раскрытие вложенных `details`, доступность и сохранение неотредактированных данных. Если новая секция меняет модель или бизнес-правила, необходимы соответствующие изменения API, миграции и тесты по их области ответственности.
3. Используйте локальные CSS-токены `.compact` в `event-playground.module.css`: `--editor-control-height`, `--editor-control-radius`, `--editor-control-border`, `--editor-field-gap`, `--editor-group-gap`. Цвета приложения используют существующие переменные вроде `--color-muted`, `--color-accent`, `--color-line`; не импортируйте токены Website. Переиспользуйте `Field`, `CompactFieldHints`, `MultilineField` и текущие классы до введения новых стилей.
4. Для изменений поведения добавьте целевые тесты формы и сохранения, включая исторические значения, условные поля и переключение типа; для финансов — тесты доменного расчёта и серверной валидации. Отдельно подтвердите интеграцию через безопасный изолированный E2E-контур согласно `AGENTS.md`. Наличие файлов тестов само по себе не подтверждает их прохождение.
