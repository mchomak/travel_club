# JSON маршрута Travel Club — версия 1

Передайте GPT этот документ и файл `trip-json-example.json` вместе с пожеланиями к поездке. Попросите вернуть готовый JSON в UTF-8 без комментариев и Markdown. Сохраните ответ в файл с расширением `.json`, откройте «Поездки» → «Импорт JSON» и выберите этот файл.

Обычный импорт создаёт новую поездку. Чтобы обновить существующую, откройте её проверку маршрута и выберите «Загрузить исправленный JSON»: перед применением будет показано сравнение, а выбранные изменения потребуют подтверждения. Кнопка «Экспорт JSON» выгружает сохранённые данные, в том числе внутренние заметки и цены. Публичная ссылка и рассчитанные суммы не экспортируются: сервер рассчитывает суммы заново. Фотографии из библиотеки представлены идентификаторами; загруженные пользователем фото дней включаются в экспорт в поле `photos` как изображения в формате base64. При создании новой поездки сервер проверяет и сохраняет их заново. Максимальный размер файла импорта и экспорта — 10 МБ; если экспорт превышает лимит, приложение сообщает об этом и не создаёт неполный файл.

Для GPT: не выдавайте предположительные цены, бронирования, часы работы, координаты и ссылки за подтверждённые. Если цена неизвестна, используйте `unit_price: "0"`, `price_pending: true`, `included: false` и уточните это в заметке. Используйте уникальный UUID для каждого дня; `day_id` события должен точно совпадать с `id` его дня. После импорта человеку следует проверить даты, время, цены и доступность.

## Описания и заметки

`description` содержит полезное клиенту описание впечатлений и программы. Не дублируйте в нём данные, для которых есть отдельные поля: даты, время, города и пункты отправления/прибытия, адрес, цену, валюту, ссылки и перечень `stages`. Например, время экскурсии запишите в `start_time`/`end_time`, адрес — в `location`, ссылку на карту — в `map_url`. Если добавить нечего, оставьте описание пустым или опустите его.

`client_note` предназначено для полезных клиенту рекомендаций и условий участия, например одежды или правил встречи. `internal_note` — для служебных задач, статуса проверки, договорённостей с поставщиком и уточнения стоимости. Не помещайте служебные замечания в `description`, `client_note` или `stages.notes`: описание этапа видно клиенту. Эти правила действуют для заметок поездки, дня и события.

Не выдумывайте номера рейсов, перевозчиков, расписание, цены или подтверждения бронирования. Используйте только предоставленные или проверенные сведения; неизвестные необязательные значения опускайте или записывайте как `null`, если поле допускает это. Неизвестную стоимость обозначайте через `price_pending`, а служебную задачу по её уточнению — в `internal_note`. Не копируйте учебные цены, время и ссылки из примера в реальный маршрут.

## Общий формат

В корне документа находятся обязательные поля `format` — всегда `"travel-club-trip"`, `version` — всегда число `1`, `trip` — объект поездки, а также необязательное поле `photos` для загруженных изображений из экспорта. При подготовке нового маршрута вручную поле `photos` не требуется. Не добавляйте неизвестные поля: они отклоняются. Необязательные поля можно опускать: сервер применит значения по умолчанию. Пустая строка записывается как `""`, отсутствие необязательного значения — `null`, пустой массив — `[]`.

При экспорте существующей поездки поле `reimport` содержит идентификаторы поездки и снимка для сравнения. Сохраняйте его без изменений при исправлении файла. Оно не содержит публичную ссылку. Файлы без этого поля по-прежнему подходят для создания новой поездки, но не позволяют надёжно сравнить исправления с исходной ревизией. Старые установки, не поддерживающие `reimport`, могут отклонить такой файл.

Даты записывайте как `ГГГГ-ММ-ДД`, местное время — как `ЧЧ:ММ` без часового пояса. Денежные и другие десятичные значения передавайте строками с точкой, например `"1500.50"`. Участники, позиции и длительность записываются целыми JSON-числами.

## trip — поездка

| Поле | Значение |
| --- | --- |
| `internal_title` | Обязательно. Внутреннее название, 1–200 символов. |
| `client_title` | Название для клиента; по умолчанию пустое. |
| `start_date`, `end_date` | Обязательно. Первый и последний день включительно; конец не раньше начала, максимум 3660 дней. |
| `participants` | Обязательно. Целое число участников от 1 до 10000. |
| `base_currency` | Трёхбуквенный код валюты заглавными латинскими буквами, например `RUB`; по умолчанию `RUB`. |
| `internal_note`, `client_note` | Внутренние и клиентские заметки, каждая до 10000 символов. |
| `status` | `draft` — черновик, `ready` — готова, `archived` — архив; по умолчанию `draft`. |
| `pricing_mode` | `markup` — наценка на себестоимость; `target_margin` — целевая маржинальность. По умолчанию `markup`. |
| `pricing_percent` | Неотрицательный процент строкой; для `target_margin` строго меньше 100. По умолчанию `"0"`. |
| `cover_photo_id` | Идентификатор фотографии из встроенной библиотеки или `null`. Для нового маршрута обычно опускайте. |
| `days`, `items`, `rates` | Массивы дней, событий и курсов; по умолчанию пустые. |

## days — дни

| Поле | Значение |
| --- | --- |
| `id` | Уникальный UUID. Укажите его, если на день ссылаются события. Если поле опущено, сервер создаст идентификатор. |
| `date` | Обязательная уникальная дата в диапазоне поездки. |
| `country`, `city`, `place` | Страна, город и место текстом. |
| `title`, `status` | Название и текстовый статус дня. |
| `internal_note`, `client_note` | Внутренние и клиентские заметки. |
| `photo_id` | Идентификатор фотографии из библиотеки, загруженной фотографии из поля `photos` или `null`. |
| `map_start`, `map_end`, `map_leg_modes` | Настройки карты; описаны ниже. |

Текстовые поля необязательны. Дни с одинаковой датой или ID недопустимы. Отсутствующие дни диапазона будут созданы автоматически. Для нового маршрута не заполняйте карту без проверенных координат: её можно настроить в конструкторе.

## items — события и расходы

Обязательны `type`, `title`, `calculation_mode`, `currency`. Остальные поля можно опустить.

| Поле | Значение |
| --- | --- |
| `id` | Уникальный UUID события; если отсутствует, создаётся автоматически. |
| `day_id`, `end_day_id` | UUID начала и окончания из `days`. `null` у `day_id` означает общий расход без привязки к дню. Если `end_day_id` задан, он тоже должен существовать. |
| `position` | Порядок внутри дня, целое от 0 до 10000; по умолчанию 0. |
| `type` | Категория: `flight`, `train_bus`, `transfer`, `hotel`, `excursion`, `activity`, `rental`, `insurance`, `meal`, `other`. |
| `subtype` | Необязательный подтип, допустимые значения перечислены ниже. |
| `title`, `description`, `location` | Название, описание и место. Название обязательно, до 200 символов; описание до 10000, место до 200. |
| `start_time`, `end_time` | Местное время начала и конца или `null`. Конец должен быть позже начала с учётом даты и смещений UTC, если они заданы. |
| `departure_country_code`, `arrival_country_code` | Коды стран ISO alpha-2, например `RU`, `JP`, либо `null`. |
| `departure_city`, `arrival_city`, `departure_label`, `arrival_label` | Города и названия пунктов отправления и прибытия. |
| `departure_utc_offset_minutes`, `arrival_utc_offset_minutes` | Для `flight`, `train_bus`, `transfer`: оба целых смещения от UTC в минутах от -840 до 840 либо оба `null`. Учитывайте дату и сезон. |
| `airport_before_minutes`, `airport_after_minutes` | Минуты до и после перелёта, целые 0–1440; по умолчанию 180 и 60. |
| `external_url`, `map_url`, `booking_url` | Необязательные полные http(s)-ссылки на ознакомительный ресурс, карту и бронирование/оплату соответственно; или `null`. |
| `publish_external_url` | Показывать ли все три ссылки клиенту (`true`/`false`, по умолчанию `false`). Старое поле `external_url` остаётся ссылкой на ресурс. |
| `stages` | Необязательный упорядоченный массив этапов события: `id` (UUID, можно опустить), `title`, `start_time` и `end_time` (`HH:MM` или `null`), `notes` (описание для клиента), необязательные `location` (название места, до 200 символов), `address` (адрес, до 500 символов) и `map_url` (полная http(s)-ссылка или `null`). Этапы не создают отдельных событий и не меняют смету. |
| `internal_note`, `client_note` | Заметки для сотрудников и клиента. |
| `included` | Включать стоимость в смету: `true`/`false`, по умолчанию `true`. |
| `price_pending` | Цена ожидает уточнения: `true`/`false`, по умолчанию `false`. При `true` обязательно `included: false`. |
| `currency` | Валюта цены из трёх заглавных букв. Если отличается от базовой, добавьте курс в `rates`, даже для нулевой цены. |
| `unit_price` | Цена за единицу строкой, от 0 до 999999999999, максимум 2 знака после точки; по умолчанию `"0"`. |
| `quantity` | Количество строкой, больше 0 до 10000, максимум 4 знака; по умолчанию `"1"`. |
| `participants_override` | Число участников события, не больше числа участников поездки, или `null`; иначе используются все участники. |
| `capacity` | Вместимость единицы для `capacity` или номера для `hotel`, положительное целое или `null`. |
| `rooms_override` | Ручное положительное число номеров для `hotel` или `null`; заменяет расчёт по вместимости. |
| `duration_days` | Положительное целое число дней для `per_day` и `per_person_per_day`, по умолчанию 1; период не должен выходить за поездку. |
| `check_in`, `check_out` | Для `hotel`: даты заезда и выезда; выезд позже заезда, ночи в диапазоне поездки. Привязанный день — день заезда. |
| `check_in_time`, `check_out_time` | Местное время заезда и выезда или `null`. |
| `map_place`, `map_end_place`, `auto_transfer` | Данные карты и автоматического трансфера; при создании нового маршрута обычно опускайте. |

Допустимые значения `subtype` зависят от `type`:

- `train_bus`: `bus`, `train`, `other`.
- `transfer`: `bus`, `train`, `taxi`, `car`, `walk`, `rental`, `water`, `other`.
- `rental`: `bus`, `train`, `taxi`, `rental`, `water`, `other`.
- `meal`: `restaurant`, `cafe`, `bar`, `street_food`, `other`.
- `excursion`, `activity`: `excursion`, `activity`, `other`.
- `insurance`: `insurance`, `other`.
- `other`: `insurance`, `sim`, `communication`, `visa_fee`, `service_fee`, `other`.
- Для остальных типов укажите `null` или опустите поле.

Режимы `calculation_mode`:

- `per_person`: цена × участники × количество.
- `fixed`: цена × количество.
- `capacity`: цена × округлённое вверх (участники / вместимость) × количество. Нужна `capacity`.
- `hotel`: цена номера × число номеров × число ночей. Нужны даты и `capacity` или `rooms_override`.
- `per_day`: цена × дни × количество.
- `per_person_per_day`: цена × участники × дни × количество.
- `manual`: итоговая сумма в `unit_price`.

Сервер проверяет данные и рассчитывает итоги.

## Правила формирования событий и вложенных этапов

1. Каждую отдельно оплачиваемую, бронируемую или организуемую услугу оформляйте самостоятельным объектом в `items`.
2. `stages` описывают программу цельной услуги, приобретаемой единым пакетом. Этапы не имеют собственной стоимости и не создают отдельных событий.
3. Не объединяйте независимые расходы в одну фиксированную сумму ради компактности.
4. Не заменяйте финансовые поля перечислением расходов в `internal_note` или `stages.notes`.
5. Для каждого самостоятельного события выбирайте режим `calculation_mode`, соответствующий фактической единице тарификации.
6. Исключайте двойной учёт: включённые в пакет части не добавляйте в смету повторно; услугу сверх пакета учитывайте отдельно, если она входит в смету Travel Club.
7. Если неизвестно, входит ли услуга в пакет, укажите неопределённость в заметке и не придумывайте условия.
8. При генерации учитывайте актуальные правила и замечания валидатора, если они предоставлены, а также ограничения этой инструкции.
9. При исправлении JSON сохраняйте UUID объектов, которые не требуется удалять или заменять, и согласованность ссылок между ними.
10. Для исправления отдельных замечаний не переписывайте весь маршрут без необходимости.
11. Неизвестные данные оформляйте предусмотренными схемой способами; не выдавайте предположения за подтверждённые сведения.
12. Не добавляйте неизвестные поля и не меняйте версию формата без основания.

**Пакетная экскурсия.** Готовая экскурсия на Пхи-Пхи стоимостью 3 400 THB на человека, включающая трансфер, катер, остановки и обед, — одно событие `excursion` с режимом `per_person` и ценой `"3400"`. Программу можно описать в `stages`: трансфер, регистрация, катер, Maya Bay, лагуна, обед и возвращение. Стоимость указывается только у события.

**Самостоятельная программа.** Если Travel Club отдельно организует и оплачивает день в Бангкоке, создайте последовательные `items`: трансфер до Королевского дворца (`transfer`, `fixed` или `capacity` по условиям тарифа), посещения дворца и Wat Pho (`excursion`, `per_person` при цене на человека), обед (`meal`, `per_person` при цене на человека), паром (`transfer`, режим по фактическому тарифу) и посещение Wat Arun (`excursion`, `per_person` при цене на человека). Укажите известные время, описание, стоимость, адрес и необходимые ссылки для каждой услуги; неизвестные сведения не выдумывайте.

**Неизвестная цена.** Например, для услуги с неуточнённой ценой используйте `"unit_price": "0"`, `"price_pending": true`, `"included": false` и поясните в заметке, что цена ожидает уточнения. Если валюта отличается от базовой, необходим её курс в `rates` даже при нулевой цене.

**Исправление JSON.** Если замечание относится только к названию события, измените его `title`, сохранив `id`, `day_id`, `reimport` и остальные не затронутые данные. Внутри существующей поездки загрузите исправленный файл для сравнения и выберите нужные изменения. Обычный импорт из списка создаёт отдельную поездку и переназначает UUID.

## rates — курсы валют

Каждый объект содержит `currency` — код валюты события — и `rate` — строку с положительным курсом до 1000000 и максимум 8 знаками после точки. Курс показывает, сколько единиц базовой валюты стоит одна единица валюты события. Например, при базовой валюте RUB: `{ "currency": "JPY", "rate": "0.65" }`. Не повторяйте валюты; курс базовой валюты равен 1 и его можно не указывать.

## Служебные поля карты при экспорте

`map_start`, `map_end`, `map_place`, `map_end_place` — `null` или объект с полями `name` (непустая строка), `address` (строка), `country_code` (ISO alpha-2 или `null`), `latitude` и `longitude` (числа координат), `provider` (`geoapify`, `manual`, `google_link`), `provider_place_id` и `source_url` (строка или `null`).

`map_leg_modes` — массив объектов `{ "from_key": ..., "to_key": ..., "mode": ... }`. Ключ точки: `day:start`, `day:end`, `item:UUID:start` или `item:UUID:end`; режим: `drive`, `walk`, `transit`.

`auto_transfer` содержит такие же ключи и режим (`drive` или `walk`), а также `duration_seconds` (неотрицательное целое) и `source_signature` (строка). Эти поля предназначены для переноса экспортированных карт; не придумывайте их для нового маршрута. При импорте UUID переназначаются, а ссылки карты обновляются.

## Если импорт сообщает об ошибке

Исправьте указанное поле и выберите файл снова. Проверьте совпадение UUID дней, диапазон дат, типы и подтипы, валютные курсы и условия стоимости. После импорта проверьте расписание, заметки и смету в конструкторе: GPT может ошибаться.
