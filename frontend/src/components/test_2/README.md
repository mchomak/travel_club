# Living Issue — эксперимент /test_2

Открыть `http://localhost:3000/test_2`. `#start` пропускает opening и открывает исходную шапку/hero. `#story` — форма заявки только в эксперименте. Контрольный `/test` сохраняет свои исходные anchors и поведение.

- `issue-content.ts`: все тексты opening и фотографии. `coverImage` сейчас использует `/test/memory-ferry.jpg`; `spread` содержит заголовок, номер, координаты, основной кадр общего стола и маленький кадр чая. Можно заменить image-объект здесь на `{ src, alt, width, height }`, разместив новую фотографию в `public/test_2/`.
- `living-issue.tsx`: семантическая обложка и декоративный разворот, lifecycle нативной прокрутки. Passive scroll/resize + rAF обновляют три CSS-переменные без React renders. IntersectionObserver выключает расчёт за пределами сцены.
- `living-issue.module.css`: полностью scoped композиция, глубина, размеры, easing через прогресс. Обёртка занимает 140svh; sticky viewport — 100svh. Обложка раскрывается, разворот приближается, теряет перспективу и уходит обычным скроллом в неизменённый hero. Общая фотография, текст, шрифты, цвет и линии связывают обе композиции.
- `editorial-home.tsx`, `lead-form.tsx`: зафиксированные копии исходных деревьев. Единственные смысловые отличия — якоря. Данные, логика demo-заявки, CSS, фотографии и fonts импортируются из `../test` без изменения оригиналов. При будущем изменении контрольной версии синхронизировать эти копии нужно намеренно.

Desktop раскрывает обложку с умеренным rotateY. Телефон раскрывает её вверх и показывает вертикальный разворот с естественной высотой текста. Короткий landscape использует горизонтальную композицию без 3D. Reduced motion показывает статичную обложку и обычную прокрутку, без дополнительного пустого пути. Контент и anchors работают без JS. Клавиатурный пропуск переводит focus к содержимому; следующий skip-link остаётся внутри основного сайта.

Проверки: `npm.cmd run lint`, `npm.cmd run typecheck`, `npm.cmd run build`; `npx.cmd playwright test e2e/living-issue.spec.ts e2e/test-home.spec.ts`. Для проверки на другом dev-порту задать `PLAYWRIGHT_BASE_URL`. Финальная production-версия доступна через существующий frontend Docker service на 3000.
